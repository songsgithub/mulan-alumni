# 前端设计规范 · Mulan Public Site

> 本文件是**前端实现的唯一权威来源**。任何新增页面 / 组件都必须先符合本规范，
> 再写代码。规范与代码不一致时，以本规范为准；确需偏离的，先改本文件。

---

## 0. 一句话定位

**Mulan Public Site 是一个"活动展示站"，不是"制度说明站"。**

它面向互联网大众（含国际捐赠者、合作伙伴、未来学员），
只回答三个问题：**我们在做什么、发生过什么、你可以拿到什么。**

### 0.1 硬性禁止（Public Domain）

| 禁止 | 说明 |
| --- | --- |
| ❌ 出现任何登录 / 注册入口 | 公众域的**每一个页面、每一个断点**都不得出现 `Log in` / `Sign in` / `Join` / `成员登录` 之类的链接或按钮 |
| ❌ 出现互助团的规则、制度、流程说明 | 经费标准、审批流程、报销规范、邀请码规则、5 天时限、角色定义——**一律不公开**。这些只存在于管理端 |
| ❌ 出现内部术语 | `活动方案` `活动反馈` `报销单` `核定金额` `流水号` `待审批` `项目组` `团长` 等运营词汇不出现在公众域 |
| ❌ 出现解释性长文 | 不写"本系统用于……""普通成员无需注册……"这类面向系统的自我说明 |
| ❌ 出现内部集合数据 | 方案、反馈、报销、付款、团成员、财务凭证（访问控制层面已关闭，页面层不得绕过） |

> **例外（2026-10-31 用户明确要求）**：**已解散的互助团在公众站照常展示**——
> 主页、活动、资料一律不屏蔽，历史做的事算数，不能因为团停了就把成果抹掉。
> 但公众域**不出现「解散」这个词**（内部治理术语，且太终结性，容易被读成"项目黄了"）：
> 团主页上只用一行灰字讲事实——「这个互助团现在没有组织新活动了，已经办过的活动都留在这儿。」；
> 列表页、成果流、团卡片**一律不加状态标记**（加标像讣告）。
> 判断依据在 `src/lib/public-data.ts`（公开读取层不再按 `status` 过滤）与 `cohorts.status`。
>
> ⚠️ **但"现状数据"要分开算**（2026-10-31 第三十二轮）：首页那三个数字与地图是**现状**，
> 只算还在组织新活动的团（`getCircles(200, { activeOnly: true })` + `getPublicStats` 的团数）——
> 免得首页写着 54 个团、地图上却数出 55 个。
> 「场活动 / 人次参与」照旧按公开成果算（办过的活动算数，与"不屏蔽历史"一致）。
> 公开站的团列表页（`/circles`）**仍然列出已解散的团**，否则它的主页就没人找得到了。

> **例外（2026-10-31 用户明确要求）**：公众站顶栏导航右侧加一条竖线，
> 竖线后是「工作台」入口（**新标签**打开工作台域 `connect.*` 的登录页），再往右是紫色胶囊「联系我们」。
> 这是公众域**唯一**允许的登录指向；文案在 `src/content/site.ts` 的 `nav.workspace` 与 `nav.contact`。
>
> **「加入我们」→「联系我们」（2026-11-02 第三十四轮）**：顶栏紫色胶囊与窄屏抽屉里的入口
> 改叫「联系我们」，指向 `/contact`（文案见 `site.nav.contact`）。

### 0.2 允许出现的内容

公众站的**主内容是"大家的连接成果"**，不是文章：

- 一条条**成果卡片**：谁（哪个互助团、哪个城市）做了什么、多少人参与、产出了什么
- 现场照片、参与者的一句话、可直接取用的模板
- 已公开的学习资料（可下载）
- 可公开的数字（多少圈、多少人、多少场活动）
- 合作与联系入口（邮箱 / 外链）

**不做的事**：不写成叙事文章、不做"关于我们"的自我说明、不做长段落解释。
读者要的是"看看别人做成了什么，然后拿一份走"。

### 0.3 站型：成果瀑布流，不是博客

公众站是**社交型成果流**，不是博客。三条判据：

| 判据 | 博客（不要） | 成果流（本项目） |
| --- | --- | --- |
| 排列 | 一篇接一篇往下读 | **瀑布流**，高矮错落，一屏扫完十几条 |
| 主角 | 文章 | **人**：谁做的、哪个圈、哪个城市 |
| 卡片 | 统一的大图 + 标题 + 摘要 | **多种卡片形态**：照片卡 / 话语卡 / 文件卡，混排 |
| 叙事 | 有"最新活动 → 精选 → 圈 → 资料库"的分段推进 | 首页即成果流，筛选替代分段 |

### 0.4 语言

**全站简体中文。** 包括页面文案、导航、按钮、表单标签、空状态、报错提示、
演示数据（互助圈名、活动标题与正文、资料标题与正文）。
西文只在专有名词（Ant Foundation、AI）出现。

## 1. 色彩

### 1.1 黑白灰为底，唯一强调色只给"能被操作的东西"

版式骨架是纯黑白灰（近黑的暖调中性色，不刺眼），**唯一的彩色是强调色，
只允许出现在交互元素上**——按钮、输入框焦点、链接悬停、表单选中态。
这样页面依然是克制的黑白编辑风格，但"可以点的地方"一眼可辨，且带着温度。

```
--fg          #1a1614   主文字 / 主图形（近黑，暖调）
--bg          #ffffff   页面底色
--muted       #6f6862   次要文字
--faint       #a39b93   三级文字 / 占位
--rule        #e6e1db   1px 分隔线（暖灰）
--surface     #f7f5f2   浅色区块底（暖白）
--inverse-fg  #ffffff
--inverse-bg  #1a1614   反色区块
--accent      #b4463c   唯一强调色：深砖红
--accent-soft #fbf1ef   强调色的极浅底
```

- **强调色只给交互元素**：主按钮、输入框聚焦边框、链接悬停、选中态。
  版式、标题、背景、图表一律用黑白灰。
- 强调色**不做大面积底色**，不做渐变；反色区块（`--inverse-bg`）仍是最大的"重音"手段。
- 暖调中性灰（`#f7f5f2` / `#e6e1db`）替代纯冷灰，让页面有纸感而不是屏幕感。

### 1.2 颜色使用比例（视觉基准）

| 角色 | 占比 |
| --- | --- |
| `--bg` | ~70% |
| `--surface` / `--inverse-bg` | ~20% |
| `--fg` / `--muted` | ~10% |

## 2. 字体

两套字体，不多不少：

| 角色 | 字体 | 用途 |
| --- | --- | --- |
| Display | `Instrument Serif`（400 + italic） | Hero 大标题、章节标题、事件标题 |
| UI | `Inter`（400 / 500 / 600） | 正文、导航、标签、按钮 |

- Display 字体**只用于 h1 / h2 / 事件标题**，正文一律不用。
- 禁止引入第三套字体、禁止引入图标字体、禁止 emoji 作为图标（用文字或 CSS 形状）。

### 2.1 字号阶梯（面向 27–55 岁读者，基准 17px）

受众里有四五十岁的民宿管家，**小字是硬伤**：正文不低于 17px，行高放宽，
辅助信息不低于 15px，中文正文行高比西文更需要呼吸感。

| Token | 字号 | 行高 | 字距 | 用途 |
| --- | --- | --- | --- | --- |
| `display-xl` | `clamp(3.25rem, 8vw, 7rem)` | 0.98 | -0.02em | Hero 标题 |
| `display-lg` | `clamp(2.5rem, 5.2vw, 4.5rem)` | 1.04 | -0.015em | 章节标题 |
| `display-md` | `clamp(2rem, 3.2vw, 2.75rem)` | 1.14 | -0.01em | 卡片标题 / 详情页标题 |
| `title` | `1.375rem` | 1.35 | 0 | 小标题 |
| `lead` | `clamp(1.125rem, 1.4vw, 1.4375rem)` | 1.75 | 0 | 导语 / 引文 |
| `body` | `1.0625rem` | 1.85 | 0 | 正文 |
| `small` | `0.9375rem` | 1.65 | 0 | 辅助信息、日期地点 |
| `eyebrow` | `0.9375rem` | 1.4 | 0.1em | 眉标签 |

- 字号一律用 `rem`；需要随视口缩放时用上表的 `clamp()`，**不得在页面里另写 clamp**。
- **正文最小 17px**，`small` 与 `eyebrow` 最小 15px；任何地方不得出现 15px 以下的文字。
- 中文段落每行 30–40 字为佳：正文列最大宽 `760px`。

### 2.2 中文排版

- 全站简体中文。中文没有词间空格，排版靠**字距与行高**建立节奏：
  标题字距收紧（`-0.02em` ~ `-0.01em`），正文字距为 0，行高 1.85。
- **不用斜体强调中文**（斜体中文是伪斜体，很难看）；强调改用字重、颜色或位置。
- 眉标签（eyebrow）中文不做全大写，用字距拉开的小号字 + 强调色。

## 3. 空间与栅格

### 3.1 间距（用 Tailwind 默认的 4px 基准，不再自研）

- **间距一律用 Tailwind 工具类**（`p-4` `mt-8` `gap-6` …），基准 0.25rem。
  **不要**在 `@theme` 里自造 `--spacing-*` 阶梯：Tailwind v4 一旦看到 `--spacing-*`，
  就会把所有数值类（`h-12` `p-6`）改读 `--spacing-<数字>`，未定义的会整条失效
  （`h-12` 会去读不存在的 `--spacing-12` → 高度失控）。
- 章节垂直留白由页面自己的 `Container` 类决定（`pt-10 pb-8 md:pt-14 md:pb-10`），不另造 `--section-space` 之类的 token：
  `Section` 组件只负责**底色 + 顶部分割线**，留白是页面的事。
- 业务端的组件尺寸由组件库保证：按钮 ≥44px、输入框 ≥48px、正文 ≥17px（见 §2.1）。

### 3.1.1 页面顶边：一条线，不许跳（2026-10-25 第十四轮定稿）

**每个页面的第一个标题块，都从同一条线开始；翻页时标题不许上下跳。**

| 域 | 顶边落点 | 规则 |
| --- | --- | --- |
| 工作台 | **距视口顶 97px**（页头 65 = 64 + 1px 边框 + `main` 的 `py-8` 32） | 所有页面的 `h1` 顶边一律 97px |
| 公众站 | **距视口顶 133px**（站点页头 77 + `md:pt-14` 56） | 所有页面的页头块一律从这里开始，`h1` 顶边 178px |

> 公众站的站点页头 2026-10-25 第十五轮由 72.4px 改为 **77px**：
> 导航项改成 44px 的触控高度（`min-h-11`），页头纵向留白相应从 `py-5` 收到 `py-4`，
> 净增 4.6px。**全站一起移**（页头是共用的），所以"一条线"的规则不受影响。
> 公众站 7 个页面的 `h1` 顶边实测 177.8–178.8px，最大差 1px。

- **工作台**：页头用 `PageHeader`，标题行**顶对齐**（`items-start`），标题 `self-start` 钉在行顶。
  右边有没有 44px 的操作按钮、徽标有多高，标题都不动。
  ⚠️ **不要**用底对齐（`items-end`）：那会把标题往下压 12px，于是"有按钮的页"标题在 109px、
  "没按钮的页"（工作台首页）标题在 97px，翻页面时标题会跳——那是没对齐，不是设计。
- **公众站**：页头留白统一 `pt-10 pb-8 md:pt-14 md:pb-10`；
  首页 / 成果详情 / 互助团详情 / 资料详情 / 内页页头 / 404 **全都用这一套**，不再各写各的。
  眉标签到标题的间距也统一 `mt-6`（成果详情首行是 chip 行、比眉标签高，用 `mt-2` 补平，
  最终标题仍落在同一条线上）。

### 3.1.2 移动端适配（2026-10-25 第十五轮重做）

> ⚠️ **第十五轮之前的那版不算数**：只做到了"不横向溢出 + 触控目标够大"，
> 排版还是"缩小版桌面"——导航硬塞在一行、宽表靠横向滚、页面里套可滚动框。
> 第十五轮按 iOS HIG / Material 3 的通行做法重做，下面是定稿。

**手机不是"缩小版桌面"，是另一套排版。** 六条硬规矩：

1. **导航进抽屉，不硬塞一行**
   - 公众站：`md`（768px）以下，顶栏只留 **logo + 汉堡按钮**，导航进**左侧抽屉**
     （shadcn/ui 的 `Sheet side="left"`）；`md` 以上恢复横排。
   - 工作台：**`lg`（1024px）以下一律走抽屉**。
     ⚠️ 不用 `md`（768px）：768–1023px 之间，logo + 四个导航 + 公开站/退出
     合计约 750px，挤不进 704px 的内容宽（实测会挤爆）。
   - 抽屉里的入口用 `SheetClose` 包住：点完自动收起（Next.js 是客户端跳转，不关会盖在新页面上）。
2. **不许横向溢出**。页面 `documentElement.scrollWidth` 必须等于 `clientWidth`。
   - 栅格必须显式给列：`grid-cols-1 sm:grid-cols-2`。
     **不写 `grid-cols-1` 时是 `auto` 轨道**，会被最宽那一条撑开，整页横向溢出。
   - flex 行里的长文本要 `min-w-0`（+ `truncate` 或 `break-words`），
     徽标类的小块加 `shrink-0`，窄屏改成上下两行（`flex-col sm:flex-row`）。
3. **宽表在窄屏摊成卡片，不横向滚**
   - 表格在窄屏用 `.resp-table` 摊成卡片流（同一个 `Table` 组件，CSS 换排版）。
   - ⚠️ **表单里的表格不能渲染两份 DOM**（FormData 会出现重复字段，金额翻倍），
     所以带 input 的表用 `.resp-table` 的 CSS 换排版
     （`globals.css` 里的 `@media (max-width: 639px)`），字段名靠 `data-label` 显示。
4. **触控目标 ≥ 44px**。链接与按钮都是：
   `inline-flex min-h-11 items-center`（44px），输入框 `h-12`（48px）。
   - ⚠️ 行内链接（inline 元素）的实测高度是**字体的墨盒高度**（17px 正文只有 20px 高），
     不是行高——所以只加 `py` 不够，要显式 `min-h-11`。
   - 图标按钮（清空搜索、汉堡）用 `size-11`，并把输入框的 `pr` 加到 `pr-12` 给它让位。
5. **不许"页面里套可滚动框"**。手机上的嵌套滚动会卡（滚到边界推不动页面）。
   互助团列表在窄屏**不设高度**，跟着页面一起滚；桌面才是固定高度的侧栏。
6. **弹层在窄屏变成底部面板**
   - `Sheet side="bottom"`：从下往上滑出来，高度上限 `85dvh`，内部自己滚动，
     顶部有一条拖拽把手，底部留 `env(safe-area-inset-bottom)`。
   - `Dialog`：窄屏是底部面板，`sm` 以上才回到居中模态。

### 3.2 容器与栅格

**全站宽屏原则（2026-10-24 第七轮定稿）**：公众站与管理端都按"整屏铺开"做，
**页面两侧不允许出现大块空白**。内容宽就让它宽，不要用窄容器把屏幕空着。

- **容器最大宽**：公众站与管理端统一 `2200px`（公众站 `wide` 变体 `2400px`）。
  超宽屏上以"居中 + 少量留白"收边，不做无限拉伸。
- **左右内边距**：移动 `20px` / 平板 `32px` / 桌面（≥1280px）`48px`。
  在 1920 宽的屏幕上内容**铺满**（两边各只有 `48px` 内边距）；
  2560 宽的屏幕上内容占 `2200px`，两边各留约 `228px`。
- **正文阅读列**仍限宽 `760px`（长文不铺满），**标题列**不限宽（跟随容器）。
  限宽只作用于"文字段落"，不作用于"卡片网格、表格、看板"。
- **栅格**：卡片网格 1 列（移动）/ 2 列（`md`）/ 3 列（`lg`），
  **≥1920px 升为 4 列**——宽屏要用来多放内容，而不是把 3 列拉大。
- 成果瀑布流同理：`columns-1 md:columns-2 xl:columns-3`，
  **≥1920px 用 4 列**。
- 管理端同理：`.container-page` 最大宽 `2200px`，表格与看板铺开，
  但**单个表单块仍限宽 `48rem` 左右**（表单太长一行看不完）。
- **首屏 Hero 两栏**（≥1024px）：左边是主张与数字指标，右边是**最新一条成果的现场图**，
  整块可点进成果详情。宽屏上首屏右侧不留空白；窄屏自动并成单栏。
- **页头两栏**（≥1024px）：成果详情页左边是标题与摘要、右边是**档案表**
  （互助团 / 署名 / 参与人数 / 时间 / 地点）；互助团详情页右边是三个数字。
  窄屏自动并成单栏。
- **宽屏断点用原生 CSS**：`.masonry` / `.grid-4up` 写在 `globals.css` 的未分层样式里。
  **不要**用 Tailwind 的任意断点（`min-[1920px]:`）或 `@theme` 里的 `--breakpoint-*`——
  它们会被排到 `xl` 之前，反而被 `xl` 的规则覆盖（见验收记录踩坑）。

### 3.3 圆角与阴影（**全站一套**，不再分公众站 / 业务端两套语气）

2026-10-24 第十一轮之五起，公众站与工作台**是同一个系统**：同一套 token、
同一套组件库、同一套动效。差别只在信息密度与语气，不在长相。

- **底色**：暖白 `--color-bg: #faf7f4`；卡片纯白 `--color-card: #ffffff`；
  分隔线 `--color-rule: #efe7e0`（暖浅）。工作台沿用同一组值。
- **圆角**（token 在 `globals.css` 的 `@theme`，两边通用）：
  卡片 `rounded-card` = 14px、表单块 16px、
  按钮与输入框 `rounded-control` = 10px、状态标签与徽章胶囊 `999px`。
- **阴影**：`shadow-soft` = `0 1px 2px rgba(84,56,48,.04) + 0 12px 28px -14px rgba(84,56,48,.12)`
  —— 极淡的**暖**阴影，不用冷灰阴影；悬停用 `shadow-lift` 并轻微上浮 `translateY(-2px)`。
- **字体**：全站一套无衬线（Inter + 中文本地兜底栈），`--font-display` 与 `--font-sans` 同栈；
  工作台额外优先 `ui-rounded`（macOS 的 SF Pro Rounded），系统无此字体时自动回退。
- 强调色仍是深砖红 `--color-accent`——**有女性气质但不甜腻**，靠形状与光影给温度，不靠粉色。
- 组件库主题变量（`--background` / `--card` / `--primary` / `--border` / `--ring` …）
  指向的就是上面这组暖色，**全站不再有第二套色板**。

## 4. 组件库

- **公众站**：所有样式**必须**来自 `src/components/site/` 下的共享组件。
  页面文件里**不允许**出现 `style={{}}`、`className` 里手写 Tailwind 工具类拼接版式。
  - 共享组件**本身由 shadcn/ui 拼出来**（`Card` / `Badge` / `Button` / `Separator` …），
    公众站与工作台因此是同一套长相，而不是两套平行实现：
    `Chip` = `Badge`、`ArrowLink` = `Button` 的 link 变体、`Rule` = `Separator`、
    成果卡 / 互助团卡 / 资源卡 = `Card`。
  - 页面里想微调 → **给组件加 variant**，不要在调用处拼 className。
- **动效**（2026-10-24 第十一轮之五新增，全站一套）：
  - 组件层动效由 `tw-animate-css` 提供（shadcn 的 `animate-in` / `fade-in-0` /
    `zoom-in-95` / `data-[state=open|closed]:…`）。**不装这个包，这些类全是空的**——
    弹层下拉会"啪"一下出现，没有任何进出场。
  - 内容层动效用 `src/components/site/Reveal.tsx`：元素滚进视口时**渐显 + 轻微上移**。
    纯增强：没有 JS 时内容照样可见（服务端 HTML 不带隐藏态），首屏已在视口的元素不参与动画。
  - 缓动统一 `--ease-soft` = `cubic-bezier(0.22, 1, 0.36, 1)`；
    时长：微交互 200ms、入场 700ms。
- **业务端（工作台）**：一律用 **shadcn/ui 组件**（`src/components/ui/*`，底层 **Base UI**，
  `@base-ui/react`），**不要自研**（不要手写 `ui-btn` / `ui-input` 这类 utility 当组件用）。
  - 组件：Button / Input / **InputGroup** / Textarea / Select / Label / Card / Badge / Alert / Dialog /
    Table / Tabs / Separator / RadioGroup / Checkbox / Popover / **Sheet** / Combobox（地域、互助团）
  - **输入框里带筛选标记用 `InputGroup`**（shadcn 官方 `input-group` 的做法）：
    外层画框、内层是无边框输入框，前 / 后缀位放筛选标记与清除按钮。
    标记写在框里比另起一行省地方，读者也一眼知道"正在搜哪一片"——
    工作台右侧列表的**地域筛选标记**就是这么做的（`CohortList`）。
    ⚠️ **内层输入框必须写 `!outline-none`**：全局 `:focus-visible`（品牌色方框）不在 Tailwind 分层里，
    普通 `outline-none` 压不住它——点进输入框会在**框里**画出一个紫色方框。
    焦点提示交给外层 `InputGroup` 的 `focus-within:` 环（见 `SearchSelect` 的 `COMBO_INPUT`）。
  - **全站搜索框只有一种长相**（2026-10-30 第二十四轮之二统一）：
    - **页面级搜索框**用 `console/SearchField`：**放大镜在左、清空（✕）在右**，中间是输入框；
      框高 48px、字号 17px、**胶囊**（`rounded-full`，2026-10-31 第三十轮起与公开站搜索框同一长相）。
      页面级提示词写「能搜什么」：「搜团名 / 城市 / 区县 / 项目」「搜通知标题」（不带「搜索…」省略号）。
      用它的三处：互助团列表（`CohortList`）、全部互助团名录（`CohortDirectory`）、首页图片搜索。
    - **弹层里的搜索行**用 `SearchSelect` 导出的 `ComboSearchRow`：**放大镜 + 输入框**，与页面级同一个图标。
    - 提示词格式统一成「**搜索X…**」：搜索地域… / 搜索互助团… / 搜索省份… / 搜索城市… / 搜索区县…。
      页面级搜索框的提示词写"能搜什么"（搜团名 / 城市 / 区县 / 类别），格式用「搜…」开头。
    - 触发框（还没选东西时）的文案统一「**全部X**」：全部地域 / 全部互助团 / 全部年份。
    - ⚠️ 不要再手写"圆圈 ×"或"文字链接"当清除入口：一律用 `InputGroup` 后缀位上的图标按钮。
  - **焦点样式全站一致**：**粗紫描边（2px 实线、外扩 3px）+ 焦点环**。
    `Input` 靠 globals.css 的全局 `:focus-visible` 拿到描边；`InputGroup` 的外层是 div（够不着那条规则），
    用 `focus-within:outline-2 focus-within:outline-accent focus-within:outline-offset-[3px]` 手动补齐，
    内层 input 另加 `!outline-none`。两处看起来必须是同一个样子。
  - **筛选控件三件套**（工作台）：类别 chips 用 shadcn `Button`
    （选中 = `variant="default"` 实心紫、未选 = `variant="outline"`）；
    清除筛选用 `variant="ghost"` + `✕` 图标（`CategoryFilter` / `StatsFilters` 一样）；
    筛选字段的标签间距统一 `mb-1.5`。
  - **下拉框必须用 `<Select>`（Base UI）**，不要用原生 `<select>`：原生下拉是浏览器默认长相，
    样式不可控、且在宽屏下很丑。
    ⚠️ **全站不许再出现原生 `<select>`**——第十五轮之前，工作台首页的统计筛选
    （年份 / 季度 / 月份 / 地域 / 互助团）就是原生下拉，弹层长相与宽度都不受组件库控制；
    现已全部换成组件库版（`StatsFilters` 里的 `FilterSelect`）。
  - **面板落在触发器正下方**：`Select.Positioner` 设 `alignItemWithTrigger={false}`（Base UI 默认是
    选中项盖在触发器上，手机上像错位）；`align="start"` 让面板左边缘与触发器左边缘对齐。
  - **宽度用 `--anchor-width`**（Base UI 的触发器宽度变量，不是 Radix 的 `--radix-*`）：
    `w-(--anchor-width)` 定在 Popup 上（border-box，含边框），面板与触发框**严格同宽**（官网演示即如此）。
    长选项换行，不撑宽。不要再加 `18rem` 之类的下限：200px 的触发框会弹出 288px 的面板。
  - ⚠️ **Select 的 `value` 用 `null` 表示未选**（不是空串或 `undefined`），占位文字由 `SelectValue` 的
    `placeholder` 显示；想让已选项的文字在弹层未打开时就能显示，给 `Select` 传 `items`。
  - 校验口径：弹层与触发器的**左边缘差必须是 0**；弹层不窄于触发器；
    触发器高度 ≥ 44px。
  - **可搜索下拉（地域、互助团）用 `Combobox`**：触发按钮 `Combobox.Trigger`，搜索框放在弹层里
    `Combobox.Input`，锚点自动是触发按钮；选项用 `Combobox.Item`。
  - **状态样式用 Base UI 的 data 属性**：`data-[open]` / `data-[closed]` / `data-[checked]` /
    `data-[highlighted]` / `data-[active]`，不再用 Radix 的 `data-[state=…]`。
  - **`asChild` 不存在了，改用 `render`**：`<Button render={<Link href="/x" />}>去看看</Button>`；
    `<SheetTrigger render={<Button … />} />`；`<SheetClose nativeButton={false} render={<Link … />}>`
    （渲染成 `<a>` 时要关掉原生 button 语义，否则控制台报警告）。
  - ⚠️ **全局 `:focus-visible` 样式在 Tailwind 分层之外**，普通工具类压不住它（会出现品牌红方框）；
    要去掉的地方用 `!outline-none`（见 `COMBO_INPUT`）。
  - ⚠️ **`<SelectItem>` 的值不能是空串**（会抛错）：
    「全部省份 / 全年」这类占位项用哨兵值 `__all__`，在 `onValueChange` 里映射回空串。
  - 校验口径：弹层与触发器的**左边缘差必须是 0**；弹层不窄于触发器；
    触发器高度 ≥ 44px。
  - 主题色由 `globals.css` 的 `--background` / `--primary` / `--border` / `--ring` 等变量驱动
    （指向业务端的暖色基调），换组件库不会把柔化调子改回去。
  - **命名冲突要留意**：我们的 `--color-muted`（文字色）与 `--color-accent`（强调色）
    早于 shadcn 存在，shadcn 的同名变量已改名为 `--console-muted` / `--console-accent`，
    组件里对应用 `bg-console-muted` / `bg-console-accent`。
  - 表单里的下拉框用 `src/components/console/FormSelect.tsx`：传 `name` 后 Base UI 自己渲染
    隐藏 input，值直接进 FormData。
  - **选文件不用浏览器原生的 `<input type="file">` 外观**：
    原生按钮的文案（「选择文件」「未选择任何文件」）由**系统语言**决定——
    英文系统上会露出英文，不是全站中文；它也塞在输入框里，按钮贴着上沿、
    跟输入框边框对不齐。统一做法（照片上传 / 凭证上传 / 资源上传三处都一样）：
    **隐藏的原生 input（`sr-only`）+ 一个真正的按钮 + 已选文件名**，
    文件仍留在原生 input 里，FormData 提交不变。
  - 表单里的勾选框用组件库的 `Checkbox`：勾选框本身不参与原生表单提交，
    由隐藏 input 把 `on` / 空串带进 FormData（服务端统一按 `=== 'on'` 判定）。
  - 组件尺寸是硬约束（§2.1）：shadcn 默认按钮 36px、输入框 36px、字号 14px，
    **都要按规范调大**（按钮 h-11=44px、输入框 h-12=48px、按钮字号 ≥15px）。
    已调大的：Select 触发器 48px、Tabs 44px、下拉项 44px、
    Label / Badge / Table / Tabs / Dialog / Alert / Tooltip 字号 15px、
    Checkbox 触控区 44×44（方框本体 24×24）。
  - 业务端**不手写"错误提示块"**：统一用 `Alert`（错误用 `variant="destructive"`）；
    表单外壳用 `Card`；重复明细块用 `Card`；不写死 `rgba(...)` 阴影，用 Tailwind 阴影 token。
  - **`Sheet`（`src/components/ui/sheet.tsx`）= 抽屉**，是移动端的标准容器：
    `side="left"` 给导航用（侧边抽屉），`side="bottom"` 给"从底部升起"的清单用
    （活动进度）。底部面板自带拖拽把手、`85dvh` 上限、内部滚动与安全区留白。
    抽屉里的链接要用 `SheetClose` 包住，点完自动收起。

### 4.1.1 成果卡片（瀑布流单元）

三种形态，**靠形态差异制造瀑布流的高低错落**，不做统一模板：

| 形态 | 用于 | 结构 | 高度 |
| --- | --- | --- | --- |
| `photo` | 活动现场 | 图（3:4 或 4:3）+ 日期/城市 + 标题 + 摘要 + 署名 | 高 |
| `quote` | 成员的一句话 / 复盘 | 大字标题 + 短摘要 + 署名，**无图** | 中 |
| `file` | 可取用的模板 | 文件名 + 类型标签 + 标题 + 下载入口 | 矮 |

规则：

- 图片**顶到卡片边缘**（社交感），不加卡片边框、不加阴影；卡片之间靠留白和 1px 细线分隔。
- 每张卡必须出现**归属**：团名 / 城市 / 署名三者至少其一，否则读者看不出"连接"。
- 瀑布流用 CSS `columns` 实现（`columns-1 md:columns-2 xl:columns-3`），
  子项必须 `break-inside-avoid`，否则卡片会被拦腰截断。

### 4.2.1 成果流的两组筛选

社交型成果流要同时回答"看什么"和"看谁"，所以首页有**两组筛选**：

| 组 | 取值 | URL 参数 |
| --- | --- | --- |
| 类型 | 全部 / 活动 / 故事 / 模板 | `?type=event|story|template` |
| 互助团 | 全部 / 各团 | `?circle=<cohort slug>` |

- 两组**可组合**（`/?type=story&circle=hangzhou-ai`），组合时互不覆盖。
- 筛选控件是胶囊标签（`border-radius: 999px`，§3.3 例外），选中态用 `--accent` 文字 + `--accent` 边框。
- 筛选**不用客户端 JS**，一律走 URL 查询参数 + 服务端渲染，保证可分享、可刷新、无 JS 也能用。
- 筛选区上方必须能看到"当前筛的是什么"（例如"正在看：杭州 AI 互助团"），并给一个"看全部"的退出口。


### 4.2.2 公众站的可搜索下拉（2026-10-30 补）

活动列表页（`/outcomes`）的「区域」下拉选项较多，改为**可搜索下拉**：
组件 `src/components/site/MuseSearchSelect.tsx`（Base UI `Combobox`）。

- **站点与工作台各一套**：站点用 `MuseSearchSelect`（magnolia / ink / line token、胶囊触发器、
  `rounded-[1rem]` 弹层、44px 触控），工作台用 `console/SearchSelect`（accent / fg / rule token）。
  **不混用**：两边的 token、圆角与阴影口径不同，站点不引用工作台的样式常量。
- 弹层顶部一行**放大镜 + 输入框**（提示词「搜索区域…」），输入即过滤（按文字包含匹配，中文不做拼音）。
- **匹配项在前，「全部区域」沉到最后**：既是重置入口，也不抢第一条高亮；
  键盘 ↑↓ 移动、Enter 选中、Esc 关闭（`autoHighlight` 让第一条匹配默认高亮）。
- 一个都没匹配上时，列表仍留「全部区域」，并单独给一行「没有匹配的区域」。
- 选中后条件仍写进 URL（`?region=…`），地址可分享——筛选**不靠客户端 JS 过滤数据**。

### 4.3 按钮与输入框（"柔中带刚"）

给 27–55 岁、多数是女性的用户用的控件，**不能又硬又小**：

| 维度 | 规则 |
| --- | --- |
| 尺寸 | 按钮最小高 `44px`（触控友好），输入框最小高 `48px`，字号 ≥ 16px |
| 内边距 | 按钮左右 ≥ `1.5rem`、上下 ≥ `0.7rem`；输入框左右 ≥ `1.125rem` |
| 圆角 | `2px`（唯一的版式例外，见 §3.3） |
| 主按钮 | 强调色底 + 白字，字重 500；hover 加深，不位移 |
| 次按钮 | 透明底 + 1px `--rule` 边框；hover 边框变 `--fg` |
| 输入框 | 1px `--rule` 边框、`--surface` 底；聚焦时边框变 `--accent` 并加 2px 柔光环 |
| 焦点态 | 所有可聚焦元素都要有可见焦点环，用 `--accent`，不能只靠浏览器默认 |
| 占位文字 | 用 `--faint`，比正文浅但**不能浅到看不见** |
| **鼠标指针** | **凡是能点的，光标必须是手型**：按钮、选项卡、下拉触发器与选项、轮播箭头、返回顶部、筛选项、弹层的展开按钮（`summary`）…… |

### 4.3.1 光标：可点就是手型（2026-10-30 补）

⚠️ **浏览器给 `<button>` 的默认光标是箭头**（只有 `<a href>` 才默认是手型），
Tailwind 的 preflight 也不管这件事——不写就是箭头。

- 全局兜底写在 `globals.css` 的 **`@layer base`** 里（不是裸规则）：
  `button:not(:disabled)` / `[role="button"]` / `summary` → `cursor: pointer`；
  禁用态（`disabled` / `data-disabled` / `aria-disabled`）→ `cursor: not-allowed`。
- ⚠️ **必须放在 `@layer base` 里**：裸规则（在层外）会**压过 Tailwind 的 `cursor-*` 工具类**，
  组件想临时改成 `cursor-default` 就改不了了。放层内则工具类照常覆盖。
  （同类的坑还有全局 `:focus-visible` 那条——它在层外，所以普通 `outline-none` 压不住它。）
- 下拉**选项行**也是能点的：`SelectItem` 与 `COMBO_ITEM` 都用 `cursor-pointer`，
  不用 shadcn 默认的 `cursor-default`。

### 4.4 组件书写规范

- 变体用 `variant` prop，禁止用 `className` 从外部覆写样式。
- 需要微调时，给组件加新的 `variant`，而不是在调用处拼 class。
- 所有组件 `export function`，不使用 `default export`（Next.js 官方 App Router 约定）。

### 4.4.5 互助团地图（工作台 /circle）

- **数据源**：DataV.GeoAtlas（`geo.datav.aliyun.com/areas_v3`），areas_v3 为最新一版行政区划。
  预取脚本 `scripts/fetch-geo.ts` 写进 `media/geo-cache/{adcode}.json`，
  `/api/geo/[adcode]` 先读缓存、缺了现拉并落盘。
- **下钻层级**：全国（`100000`）→ 省 → 市 → **区（县）是最小单位**，再点不再下钻。
  直辖市没有市级层（北京的省 adcode 下面直接是区），所以团的位置要**省 / 市 / 区县各存一个 adcode**，
  地图按 adcode 精确匹配，不按固定层级链推。
  ⚠️ **直辖市（110000 / 120000 / 310000 / 500000）必须跳过市级层**：
  数据里北京的 `cityCode` 是 `110100`，那个 adcode 在 DataV 上**并不存在**，
  照着下钻会 502，地图停在半路。判断看**省 adcode**，不看 cityCode 是否等于 provinceCode。
- **边界数据与层级必须同步**：换层级时先 `setGeo(null)`，等新边界到了再画。
  不清的话旧边界会被 `registerMap(新adcode, 旧边界)` 注册成新层级，地图与层级对不上。
- **图表生命周期**：地图只是工作台里的展示件——
  `resize` 前判 `chart.isDisposed()`，并包一层 `try/catch`（失败只在 console 留 `warn`）；
  卸载时 `dispose()` 之后**必须把 `chartRef.current` 置 `null`**，
  否则重新挂载会复用上一个已经销毁的实例。

- **标注**：只标有互助团的区域（数量用强调色 + 地名），其余区域留白、悬停看地名——
  35 个省名一起标会互相压住，地图反而没有重点。
- **配色**：地图直接取全站 token（`--color-accent` 数字、`--color-rule` 描边、
  `--color-surface` 空区域底色），和全站同一套颜色。
- **筛选**：类别筛选走 URL 查询参数（`?category=fuel,ai-bean`，逗号连写），服务端渲染，链接可分享。
  每个类别后面显示该类别的互助团总数；筛选后地图数字与右侧列表同步变化。
  **点类别是切换**：点一下选中，再点同一个就取消它；
  想一次清空全部，用筛选行末尾的「✕ 清除筛选」。
  筛选行按 shadcn 的筛选面板写法：**类别是可切换的按钮**（选中 = 实心主色、未选 = 描边），
  清除是**独立的 ghost 按钮**（带 ✕ 图标），不要再写成一行小字链接。
- **地图 → 列表（2026-10-30 第二十四轮）**：点地图上的一个省 / 市 / 区（县），
  右侧列表**立刻筛到这一片**，并把选中的地域以**标记**的形式写进右侧列表的**搜索框里**
  （`InputGroup`），点标记上的 ✕ 清除（同时地图回到全国）。
  - **点列表的一行只做"地图定位"，不筛列表**——否则点一下行，列表就只剩那一行，反而找不到别的团。
  - 「返回上一级」与面包屑会把筛选范围带到对应层级（回到「中国」= 不按地域筛）。
  - 层级是**受控**的（`CircleNetwork` 拿 `path`）：父级拿着它，"清除筛选 → 地图回到全国"才能对上。
  - 匹配口径：一个团同时登记了省 / 市 / 区县三个 adcode，命中任意一个即算在这个地域里。
- **规模（几百个团时）**：
  - 地图**只画数量不画点**——一个区域一个数字，逐级下钻天然完成聚合；标签用
    `labelLayout: { hideOverlap: true }` 防止挤在一起。
  - 列表**分段落 + 可搜索 + 可排序**：默认 30 条，"显示更多"继续加载；
    搜索按团名 / 城市 / 区县 / 类别过滤（搜索框带一键清空，Esc 也能清）；
    排序可切「团名（拼音，默认）/ 成员数 / 类别」。
  - **地图与列表联动**：点列表里的一个团 → 地图自动下钻到它所在的区县并高亮（砖红 + 白字）；
    点地图或面包屑 → 取消高亮。两者共用同一份 `CirclePoint`（`src/lib/circle.ts`）。
  - **两栏定高 680px，列表在��己的框里滚动**——否则几百行会把整页撑到几千像素高，
    地图画布被一起拉长，国土缩成屏幕外的一小块。
  - 模拟数据（`scripts/seed-network.ts` 生成的 318 个团）**不在公众站展示**（`isPublic: false`），
    公众站的"五个城市，五个互助团"要和数据对得上；工作台的网络图对所有角色完整可见。

### 4.4.6 互助团网络（工作台 /circles）

- `/circles`：**地图 + 列表**两栏联动。地图逐级下钻到区（县），标出每处的互助团数量；
  列表按团名拼音排，可搜索、可按类别筛选；点列表一条 → 地图定位到那个区县并高亮；
  点地图一个区域 → 列表按这个地域筛（地域标记写在**搜索框里**）。
  - ⚠️ **这一页只统计"还在运行的团"**（2026-11-01 第三十五轮）：标题数量、地图、列表
    三处都只算 `status === 'active'` 的团——**已解散的团不计入数量**。
    与公众站同一口径（现状数字只算运行中的团）；已解散的团去 `/circles/all` 名录页查
    （那里列出全部并标注「解散」），它的历史成果照常算数。
    解散一个团后回到本页，数量应当立刻少 1。
- `/circles/all`：**全部互助团名录**（地图页的「更多」入口）。几百个团用三列紧凑网格，
  不分页；搜索按团名 / 城市 / 区县 / 类别 / 团长过滤。**这一页含已解散的团**（带「解散」标记）。
- `/circles/<slug>`：**单个互助团详情**——**左窄右宽两栏**：
  - **左栏（1/3）= 互助团信息**：主页大图（banner）+ 团信息（团名 / 类别 / 所在地域 / 创建时间 / 成立时间 / 状态 / 简介）、
    团长（姓名 / 所在地 / 项目类别 / 手机 / 邮箱 / 注册时间 + 团长任期区间）、
    骨干成员（副团长 / 资源对接员 / 材料整理员 / 拍摄宣传员）；
    项目组在这里还看到状态管理与团长转移。
  - **右栏（2/3）= 活动列表**：每场活动一张卡（标题 + 日期 · 预算 · 实际支出 +
    **「申请 ✓ 审核 ✓ 反馈 ✓ 报销 ✓」四段进度**），**最新活动排在最上面**（按活动日期倒序，
    同一天按创建时间倒序）；没有活动时显示「这个互助团还没有活动。」
  - 活动卡用 `self-start`，不跟着左栏高度拉伸出空白。
- 列表里的行动入口是「**查看 →**」（不是"管理"）：点进去先看这个团的全貌。

**⚠️ 团详情页的活动进度只有四段：申请 → 审核 → 反馈 → 报销**（2026-11-01 第三十五轮）：

- 原来写的是「方案 / 反馈 / 报销」三个标记 + 一个「已实施」状态徽标，读起来像两套东西。
- 现在统一成四段，颜色说明**走到哪一环**（绿 = 已完成、紫 = 正在这一环、灰 = 还没到、红 = 被驳回要改），
  位置说明**是哪一环**：`申请`（已提交）/ `审核`（待审核 → 已通过 / 已驳回）/ `反馈`（已交反馈）/ `报销`（已提报销）。
- 团信息里的「所在地域」用的是 `location` 字段；`cohorts.region` 是它的**冗余文本快照**
  （公开站在 `regionShort` 缺失时回落到它）——**改地域时必须同步写 `region`**，
  否则两处数据打架（地图在一个省、名录写着另一个省）。

**⚠️ 互助团资料统一编辑**（2026-11-01 第三十五轮）：

- **主页图 / 所在地域 / 骨干成员**合成**一个**「编辑资料」弹窗（页头操作区），
  一次提交一起存（服务端动作 `updateCohortProfile`）。
- 为什么要合并：建团时填错地域是常事（只填到省、填错市），以前要改只能分头改、
  容易漏改一半；现在一处改完就齐。
- 地域口径与建团一致：**省必填，市 / 区县可以留空**；填到哪一级，团就落在哪一级。
- 换图可选：不选文件就不动原图。
- 权限：本团团长或项目组（团长是主要编辑者）。
- 旧的 `updateCohortCover` / `updateCohortTeam` 两个动作已删——**写入口只留一个**。
  `CohortCoverForm` / `CohortTeamForm` 相应改为**只读展示**组件。

**⚠️ 高度锁定的断点必须和布局的断点一致（2026-10-30 修）**：

- `/circles` 的两栏（地图 + 可滚动侧栏）**要到 `xl`（1280px）才成立**，
  所以外层的高度锁定也必须是 `xl:h-[calc(100dvh-…)] xl:overflow-hidden`，
  网格与侧栏同理（`xl:h-full` / `xl:overflow-hidden`）。
- 之前用的是 `lg:`（1024px）：在 **1024–1280px** 这段里，页面被锁了高度不能滚，
  而右侧列表只有 `xl:` 才自己滚（`ul` 是 `overflow-visible`）——
  于是列表下半截被 `overflow-hidden` 裁掉，**54 个团里 50 个点不到、也滚不到**。
- **1280px 以下一律让页面正常滚**（地图在上、列表在下，和窄屏一个道理）。
  两条铁律：① 锁高度的断点 ≥ 布局成立的断点；② 锁了高度就必须给里面一块滚动区。
  （`/circles/all` 用 `lg:` 是安全的——它内部那张 `Card` 自己 `overflow-y-auto`。）

### 4.5 工作台：活动 = 一次从方案到发布的完整记录

**工作台的顶栏**（`layout.tsx`）：

- **常驻**（`sticky top-0`）：页面往下滚时导航不能跟着跑掉；半透明底 + 背景模糊，下面的内容透上来也读得清。
- 顶栏只有三块：`品牌 + 角色徽标` ｜ `主导航` ｜ `公开站链接 + 用户 + 退出`。
- 主导航：**活动 / 互助团**，**「资源」只给项目组**。当前所在的那一项是**填色药丸 + 深色字**（`bg-fg text-inverse-fg`），
  别人是淡字——进到哪一层要一眼看得出。判定用 `usePathname`（`WorkspaceNav`），
  路由组 rewrite 过的路径（`/circles` → `/network`）两个都要匹配，否则不亮。
- 不按"方案 / 反馈 / 报销 / 审批 / 发布"摊成一堆 tab——那是数据表，不是流程。

**页头统一用 `PageHeader`**：左边标题（+ 至多一行短的说明），右边操作。
说明只写"是什么"，**不解释"怎么用"**——用法在页面里看得见，不必再说一遍。

- **标题一律从页面内容左边缘起排**（实测 48px），工作台每个页面都一样：
  首页的问候语（"夜深了，××"）也必须和「互助团（54）」的左边缘**完全对齐**——
  翻页面时标题要原地不动。为此 `PageHeader` **不提供给标题单独加内缩的 prop**：
  之前首页给问候语加了 32px 左内缩，结果它比别的页面右移一截，看着像两套版式。

**详情页的「返回上一级」（2026-11-02 第三十八轮定）**

- 统一用 `src/components/console/PageBackLink.tsx`：**箭头图标 + 「返回XX」**，
  文案写清楚回哪儿（返回互助团 / 返回活动）——光一个箭头太抽象，
  27–55 岁的用户看「返回互助团」四个字更省事。
- 位置在**页面左边**，不在页头右侧那排操作按钮里：
  返回是「往回走」，右上角那排是「往里走」的动作，混在一起容易点错。
- **不用面包屑**：工作台只有「列表 → 详情」一层，顶栏那四个主导航已经说明了在哪；
  面包屑是重复信息，还占竖向空间（而且会把标题顶下去，破坏 97px 那条线）。
- 它**不挤占标题的位置**：标题仍从左边缘起排、顶边仍钉在 97px，
  返回链接单独占正文区左上（互助团详情页）或吸顶条左侧（活动详情页）。

**工作台首页的进度与资金卡（2026-10-30 第二十四轮之三校准）**：

- **流程进度（申请 → 审核 → 反馈 → 报销）**：走过的圆点用**主题深紫做底 + 白勾**
  （`bg-accent` + `text-inverse-fg`，不加阴影），走过的连线用 `bg-accent/45`；
  当前那一步是白底 + 紫边 + `ring-accent-soft` 光环；没到的是灰边空心圆。
  ⚠️ **不要用深紫→粉渐变 + 粉色投影**（又花又撞色），**也不要退成浅紫底 + 紫勾**
  （太轻，看不出已完成）。
  （活动详情页的环节条 `ActivityProgress` 早就用软色：完成=绿、进行=紫。）
- **资金关键数字卡**：**不画图标**。图标只是把标题又说了一遍（钱包=预算、小猪=报销），
  四种颜色（紫 / 木兰粉 / 绿 / 红）还会跟品牌紫撞色。
  现在只留「标签 + 数字 + 一句说明」，卡片白底（`bg-card`），数字用品牌紫，
  **只有"超出预算"这种负面口径用红色**（`text-danger`）。

#### 4.5.0 页头只留标题，解释收进「帮助」（2026-10-30 第二十七轮）

以前每页顶部摆着"标题 + 副标题 + 一段解释"两三行，**页头比内容还高**，翻起来累。

- 想看的人点一下，不想看的人眼前干净——和首页、互助团页一个清爽口径。

`PageHeader` 的 `note` / `description` 两个属性保留着，但**只给还没迁移的老页面兜底**；
新页面一律把说明写进 `help`。

#### 4.5.2 四个收口问题（2026-10-30 第二十五轮之二）

用户验收时提了四个问题，逐条处置如下。

**① 邀请链接到底有没有 3 / 7 / 14 天？**
**没有。实现里只有固定 7 天**（`actions.ts` 的 `createInvitationLink` 写死
`7 × 24` 小时，`createInvitationLink` **不再接收 `validDays`**）。
「3 / 7 / 14 天三档」是**第十一轮改版前的旧说法**（那一版让人自己挑时长），
文档没跟着改，代码与文档就此对不上。

全部改成「固定 7 天」，并在规范里写明**不要再冒出新档位**。
页面文案统一成：**「链接自生成起 7 天有效；对方注册成功，链接立刻失效。」**

**② 移动端适配：互助团列表溢出**
根因：`CircleNetwork` 的栅格**没写 `grid-cols-1`**，于是窄屏下是 auto 轨道，
被地图容器的内容撑到 450px——360px 屏幕上整页横向溢出 110px。
修法：栅格显式 `grid-cols-1`（`minmax(0,1fr)`）+ 列表行内 `truncate` 补 `min-w-0`。
另外**窄屏地图只标数量、不标地名**（容器 < 480px 时 ECharts 的 label 只出数字，
并补一句「窄屏只标数量，团名看下面的列表」）——
360px 上写地名就是一团互相压着的字，比不写还糟。
体检口径：360px 下 `/`、`/circles`、`/circles/all`、`/notifications`、`/assets`、
`/settings`、`/account`、`/circles/new` 的 `scrollWidth === clientWidth`（零溢出）。

**③ 通知表没有重点、字号不匹配**

| 状态 | 字重 | 下划线 | 其它 |
| --- | --- | --- | --- |

  并加 `decoration-skip-ink`，下划线在字缝处断开、不横穿高亮块。

- **表格**：主列（通知 / 标题）吃满剩余宽度，右侧各列**定宽靠右**

**文档版式按 GB/T 9704-2012《党政机关公文格式》（2026-11-02 第三十八轮）**

打印出来的 PDF 是要归档的纸质材料，所以版式照公文国家标准来：

| 项 | 规范值 | 落地位置 |
| --- | --- | --- |
| 纸张 | A4（210×297mm） | 打印路由 `page.pdf({ format: 'A4' })` |
| 页边距 | 上 37mm、下 35mm、左 28mm（订口）、右 26mm（切口） | 同上 `margin` |
| 版心 | 156mm × 225mm | 由页边距推出 |
| 正文 | 三号 16pt | `docCss` 的 `body` |
| 文件标题 | 二号 22pt 加粗 | `docCss` 的 `h1` |
| 表格 | 四号 14pt | `docCss` 的 `table.fields` / `table.data` |
| 行距 | 固定值 28.9pt（225mm 版心 ÷ 22 行） | `docCss` 的 `body` |
| 页码 | 四号，数字左右各放一条一字线 | 打印路由的 `footerTemplate` |

**字体：不另起一套，用网站现用的 Noto Serif SC**（`public/fonts/` 里本来就有）。

- 页面版与 PDF 版**字形完全一致**——同一个活动，两处看不是同一份文档的问题不存在。
- Noto Serif SC 有**真实的 Bold 字重**（regular + bold 两个文件），`font-weight: 700`
  不会触发合成粗体；合成粗体在 PDF 里会落成 Type3 位图路径（文本不可选、放大发虚）。
- 层级靠**编号 + 字号 + 真字重**区分：文件标题 22pt Bold / 一级标题 16pt Bold /
  二级标题 16pt 常规（带「（一）」编号）/ 正文 16pt 常规。
- ⚠️ `globals.css` 的 `.activity-doc` 那套字号/行距**必须与 `docCss` 同步**——
  前者带 `!important`，优先级更高，不同步的话页面版会跟 PDF 不一样。

> 公文标准里的仿宋/黑体/楷体/小标宋是**可选**的字体规格，不是硬性要求；
> 层级辨识度靠真字重同样能达成，且不必多背 25MB 字体、不必维护两套字形。

`publishContent` 与 `publishFromReport` 都要自己查一遍报销状态，不满足就拒绝
（前端隐藏不是安全边界）。活动页里发布必然关联本次活动（`PublishForm` 的
「关联活动方案」在活动页里锁成隐藏字段，不给"不关联"的口子，否则闸门能被绕开）。
所以默认落点由服务端按角色算好再传给步骤条：

- **项目组**：待审批 → ②；反馈待采纳 → ③；报销待核定 → ④；
  团长提名了 → ⑥（轮到他把它转成公开精选）。
- **团长**：方案没提交 → ①；等审批 → ②；没填反馈 → ③；反馈已交（等采纳）→ ④（可以先按实际支出提报销）；
  反馈已采纳 → ③（提名控件在这一步）；报销没提 → ④；等待核定 → ④。
- 都没有待办时，落在**走到的最后一步**。

**环节编辑权矩阵**：

| 环节 | 团长（本团） | 项目组 |
| --- | :-: | :-: |
| ① 方案内容（主题 / 预算 / 排期） | ✅ | 只读 |
| ① 提交活动申请 | ✅ | — |
| ② 审批 | ❌ | ✅ |
| ③ 活动反馈（含实际支出） | ✅ | 只读 |
| ④ 提交报销 | ✅ | — |
| ④ 核定报销 | ❌ | ✅ |
| ⑥ 精选发布 | ❌ | ✅ |

铁律：**"能看"与"能改"分开**——没有编辑权的环节照常显示内容（谁填的、什么时候填的），
只是不能改。写权限在服务端兜底（`(workspace)/actions.ts` + 集合级 access）。

⚠️ **按团隔离必须显式写进查询条件**：Payload 的**本地 API**
（`payload.find({ overrideAccess: false })`）并不会真的按集合 access 拦查询
（同一用户走 REST 是 403，走本地 API 照样返回数据）。
所以工作台页面一律叠一层 `ownCohortWhere(user)`（见 `src/lib/console-data.ts`），
集合 access 只当第二道防线。

### 4.6 邀请链接与团长（不用邀请码）

项目组在 `/circles/new` 生成一个带 token 的**链接**（不是码），只有两种用途：

| 用途 | 链接从哪来 | 对方注册后 |
| --- | --- | --- |
| `create-cohort` | `/circles/new` | 互助团建成，**对方自动成为团长**（团只要团长一人） |
| `transfer-lead` | `/circles/<slug>` 详情页的「团长转移」 | 对方**接管**该团的团长，老团长卸任但记录保留 |

- **有效期固定 7 天**（`createInvitationLink` 里写死 `7 × 24` 小时，**不再让人选**）；
  **用过即失效**（注册成功即置为 used）。
  ⚠️ 早先写的「3 / 7 / 14 天三档」已作废：那一版让人自己挑时长，
  结果发出去的链接七成是默认档，档位反而让人以为有时限可挑。
  现在只有**一个**口径：7 天。页面与文档都这么写，不要再冒出新档位。
- 注册要填：**姓名、所在地域、项目类别（加油木兰 / AI豆计划 / 民宿管家 / 追风计划）、
  手机号、邮箱**（+ 密码）。地域用三级联动（`RegionPicker`），边界数据走 `/api/geo/[adcode]`。
- **地域可以只填到省**（2026-10-31 第三十二轮）：省必填，市 / 区县可留空，也可选了再清掉
  （下拉里第一项是「只选到省」）。填到哪一级，团就落在哪一级——
  地图按省 / 市 / 区县逐级下钻，只有省就落在省上。服务端只校验"省"，不再强制三级。
- 团名按"**类别**"自动生成（如「民宿管家互助团」），不用再手填团名与标识；
  团的所在地单独一行显示（`formatPlace`：浙江省 / 浙江省 · 杭州市 / 浙江省 · 杭州市 · 西湖区）。
- 链接指向**工作台域**（公众域的 `/join` 一律 404）。

**团长任期**：`cohorts.leaderTerms` 记每一任团长与在任时间区间；转移时老任期收口、新任期开始，
老团长的信息永远保留。团长因个人原因无法继续担任并协助推选新团长的，需向项目组申请
（提供新的「数字木兰校友会互助团活动申请表」）；**无人接任的，互助团暂停运行**（状态置「暂停」）。

**不要邀请码**：码要人肉转述、容易失效、还得单独记一个字段；链接能直接发出去。

### 4.7 资源（原"学习资源"）

资源是公开的公益物料，**全部公开，没有内部 / 公开之分**：

| 类型 | 载体 |
| --- | :-: |
| `vi` | 项目 VI（视觉识别：色卡、字体、版式） |
| `video` | 视频（外链或上传） |
| `text` | 文本（正文 + 可下载附件） |
| `image` | 图片（海报、照片） |
| `file` | 文件（模板、表格） |

- 公众站与工作台看到的是同一批资源，**没有"内部资源"**。
- 资源可关联一个互助团（贡献者），出现在该团详情页。
- **资源是项目组独占的**：上传与管理在工作台 `/assets` 做，团长与成员只去公众站 `/resources` 看。
  所以「资源」**只出现在项目组的导航里**——不是显示出来再禁用，是根本不出现；
  团长直接访问 `/assets` 会被送回工作台首页。

**工作台 `/assets` 的形态**：**一张表**（标题 / 分类 / 类型 / 文件 / 大小 / 发布时间 / 操作），
类型分页签（全部 / 文档 / 视频，带各自数量）在卡片头部。

**资源要能管理**（2026-10-30 第二十六轮补）：每行最后有「编辑」——
改标题、简介、分类、外链、换附件；删除先二次确认（公众站上立刻就没了，撤不回来）。
- **行内只留一个「编辑」，操作全在弹窗里**（2026-11-02 第四十四轮，用户定稿）：
  点「编辑」弹出一张弹窗，里面是**原值摘要 + 可改的表单 + 删除**：
  - 顶部一行只读摘要（标题 / 发布时间），改之前先看清楚；
  - 中间是表单（标题 / 分类 / 简介 / 文件 / 外链），各字段带出原值，
    「不选文件 = 保留原附件」；
  - 底部左侧「删除这份资源」（二次确认），右侧「取消 / 保存修改」。
  原来行里摆「查看」+「删除」、改还要在详情里再点一次「编辑」——
  三个意思差不多的入口只会让人犹豫；现在**一个入口进去，动作都在弹窗里摆齐**。
  「上传资源」是**创建**动作，仍直接进表单（那是新东西，本来就没有原值）。
- **地址标识（slug）不提供编辑**：改了等于换地址，已经发出去的链接会失效；
- 附件可以换也可以不换——**不选文件 = 保留原附件**，不是清空；
- 资源的写入一律走**服务端动作**（`updateResource` / `deleteResource`），
  集合的 REST 直写只给后台账号（`opsOnly`）——否则任何登录用户都能
  直接 `PATCH /api/resources/<id>` 改掉公众站上正在展示的资料。
和通知页一样是**服务端分页**：类型与页码都在地址里（`?type=doc&page=2`），
前端只拿当前这一页——资源会一直攒，不能一次全拉回来。

### 4.6 之一 账号与密码（补充于 2026-10-30 第二十六轮）

- **三种身份不变**：公众（不登录）、团长、项目组，外加只在 CMS 后台用的 ops 账号。
- **团长忘记密码**：没有邮件也没有短信，所以**自助重置做不了**
  （账号与手机号没法互相验证，谁都能填别人的邮箱要求重置）。
  只有**项目组**能发起一条**一次性重置链接**（`password-resets` 集合，7 天有效、用过即失效），
  团长自己打开链接设新密码——项目组从头到尾不知道密码。
  入口：互助团详情页「团长」卡最后一行「重置密码」。
- **资源管理**：工作台 `/assets` 每行有「编辑 / 删除」；改与删都走服务端动作，
  集合的 REST 直写只给后台账号（`opsOnly`）。

### 4.7 之一 年度预算（新增于 2026-10-30 第二十六轮）

**两个"预算"不是一回事**，混了就会算错账：

| | 是什么 | 在哪 | 谁定 |
| --- | --- | --- | --- |
| **活动预算** | 这一场打算花多少 | 活动方案里填，受**单场经费上限**约束 | 团长提、项目组批 |
| **年度预算** | 这个团**一整年**能用多少 | 工作台 `/budget` | 项目组 |

**数据模型（两层）**

| 层 | 集合 | 含义 |
| --- | --- | --- |
| 统一 | `annual-budget-settings` | 项目组一次设定某年度的**默认额度**（一年一行） |
| 单团 | `cohort-budgets` | 某个团单独设的额度（**覆盖**默认值，一个团一年一条） |

优先级：**单团 > 默认**。所以"统一设置"改的是默认，"单独修改"写的是单团记录。

**另外三个运营指标（2026-10-30 补）**

| 指标 | 口径 |
| --- | --- |
| **活动次数** | 该团该年度**已开展**的活动场次（有活动反馈 = 已开展），按反馈的**实际开展时间**归年 |
| **参与人次** | 上述活动的**实际参与人数**（`actualParticipants`）之和 |
| **人均花费** | 实际执行 ÷ 参与人次；没有人时显示「—」 |

- 这三个数与「实际执行」**同源**（都只算已闭环的活动），所以人均花费是自洽的；
- 同一场活动有多条反馈时只算一次（按方案去重，取最新一条）。

**排序（2026-10-30 补）**

表头**可点**：团名 / 规划预算 / 已执行 / 剩余 / 执行率 / 活动次数 / 参与人次 / 人均花费。

- 排序写进地址（`?sort=spent&dir=desc`），刷新与分享保持同一个顺序；
- 点同一列换方向（降序 ↔ 升序），换一列则默认降序（数字列往下看更常用）；
- **空值（没设预算 / 没人可算人均）永远排最后**，升降序都一样——
  它们不是"最大"，不该占最前面的位置；
- 排序在**服务端**做（条件都在地址里，结果随地址走）。

**实际执行怎么算**（口径只有一处：`src/lib/annual-budget.ts`）

= 该团该年度**已核定**的报销金额之和：

- 只算 `approved` / `paid` 的报销单——**没闭环的不计入**（草稿 / 待审核 / 被驳回一律不算）；
- 金额取**核定金额** `approvedAmount`，不是申请金额（核减过的按核减后算）；
- 归年看**活动日期**（活动方案的计划日期），没有方案时退回报销单创建时间。

**经费页的两个视图（2026-10-30 补：首页的资金搬过来了）**

| 视图 | 讲什么 | 数据来源 |
| --- | --- | --- |
| **各团年度预算** | 团级：年度额度 vs 实际执行、余额、执行率、活动次数、参与人次、人均花费 | `cohort-budgets` + `annual-budget-settings` + 已核定报销 |
| **活动资金** | 活动级：每场活动申请的预算 vs 已核定的报销；待审队列、费用类别、超支活动、按月趋势、按项目类型、预算前十 | 活动方案 + 报销单 + 反馈 |

- 两个视图**共用同一套筛选**（年度 / 项目类别 / 状态 / 关键字，都在地址里），换视图条件不丢；
- **两个口径并列才看得出问题**：这个团今年申请的活动预算总和 vs 给它的年度额度
  —— 前者是「活动资金」视图的预算合计，后者是「各团年度预算」视图的额度。
- ⚠️ 首页原来那个「资金」标签与「数据」卡里的资金分组**已全部搬到经费页**：
  首页只管"活动与待办"，左栏「活动数据」卡里留一个入口（带当前选中的年份）。

**筛选（2026-10-30 补）**

经费页的筛选条与通知页 / 资源页同一套版式，放在表格卡片的头部一行，
条件**全部写进地址**（`?year=2026&category=a-idol&state=over&q=杭州`）：

| 控件 | 取值 | 说明 |
| --- | --- | --- |
| **年度**（下拉） | **2026 – 2030** | 年度预算这件事从 **2026 年**开始，往后给 5 年；换年度 = 换一份账，所以排在最左边 |
| 项目类别（下拉） | 全部 / 加油木兰 / AI豆计划 / 民宿管家 | |
| 预算状态（下拉） | 全部 / 还有余额 / 已经超支 / 尚未设额度 / 单独设过额度 | |
| 团名 / 城市（搜索框） | 关键字 | 输入防抖 300ms 后写地址 |

- 汇总四卡与表格**跟着筛选走**（筛出来的那些团的合计）；
- 有筛选时标题旁写「筛出 N / M 个团」；
- 筛选后没有结果 → 空状态写「没有符合筛选条件的互助团」，不是"没有互助团"；
- 团长只带一个团，**只给年度下拉**（类别与状态没有意义），搜索框也不给；
- 「统一设置」按钮在筛选条下方的标题行右侧，不挤进筛选条。

**「大多数团 5000、少数团 3000」怎么弄（批量）**

统一设置只解决"多数"；少数要不一样的，靠**勾选批量改**：

1. 「统一设置」给**全体**一个数（5000）；
2. 在表里**勾上要例外的那几个** → 出现操作条「已选 N 个团」→
   点【批量设置额度】一次设成 3000（也可以填不同的备注）；
3. 例外不想留了 → 勾选后点【取消单独额度】，这几个团**回到统一额度**。

所以经费表有**勾选列**（表头可全选），行内仍保留单个团的「单独设置」。

- 「统一设置」= 改**默认额度**；「批量设置」= 写**单团记录**（覆盖默认）。
- 额度表只增不减会乱，所以必须有"取消单独额度"这条回收路径。
- 批量动作走服务端动作（`setBudgetForMany` / `clearBudgetOverrides`），
  逐个 upsert / 删除，**逐条校验**角色与年度，不信任前端传来的任何数值。
- 项目组：汇总四卡（规划 / 执行 / 剩余 / 执行率）+ 各团表格 + **统一设置** + **单独设置**；
  团长：只看自己那个团（只读）。
- 互助团详情页「团信息」里也有一行「本年度预算」（规划 · 已执行 · 剩余），方便团长在自己的团里直接看。
- 设置页只管**单场**门槛，年度预算在经费页——设置页放一个指过去的入口，别把两件事混在一页。
- 年度预算是内部数据，**不出现在公众站**。

### 4.7 之二 密码重置（新增于 2026-10-30 第二十六轮）

**没有邮件，也没有短信**（见 §7 域名与部署约束），所以：

- **团长不能自助重置**：账号与手机号没法互相验证，谁都能填别人的邮箱要求重置，
  等于把账号送人。**只有项目组能发起**。
- **不是直接设新密码，而是给一条一次性链接**：项目组不该知道团长的密码。
  链接由团长自己打开、自己设新密码，用过即失效，**固定 7 天**有效。
- 入口：工作台**互助团详情页**的「团长」卡最后一行「重置密码」（项目组可见）→
  生成链接 → 复制 → 用微信 / 电话发给本人。
- 链接落在 `/reset-password?token=…`（工作台域，未登录可访问；公众域 404）。
- 重新生成会让这个人**还没用过的旧链接失效**（同一时间只留一条有效链接）。
- 改完密码顺带**解开登录锁定**（忘了密码的人往往已经试到被锁）。
- 集合 `password-resets` 的读写**只给后台账号**（`opsOnly`），生成与使用都走服务端动作。

### 4.8 管理端：角色分层与「提名 → 发布」

管理域按**执行方 / 审批方**分层，两套导航结构不同，写权限不同：

| 角色 | 导航 | 写权限 |
| --- | --- | --- |
| 团长 | 工作台 / 我的互助团（团详情页）/ 活动方案 / 活动反馈 / 报销 | 发起活动方案、提交反馈、发起报销、**推荐发布** |
| 项目组 | 工作台 / 互助团 / 活动方案 / 活动反馈 / 报销 / 审批队列 / 邀请码 / 学习资源 / 精选发布 | **批准活动、核定报销、发布精选**；**不发起活动** |

铁律：

- **没有权限的地方照样能看**——只读页面不因角色隐藏，避免"团长看不到成员看得到"的割裂。
- 写操作必须在**服务端**再兜一次（`(workspace)/actions.ts`），前端隐藏只是体面，不是安全。
- 成员与团长菜单**结构一致**，差别只在"能不能操作"。

**项目组的建团与团长管理**（第八轮补齐）：项目组在工作台里完成日常操作，
**不依赖 CMS 后台**——建团、换团长都在工作台有友好页面：

| 页面 | 谁能用 | 做什么 |
| --- | --- | --- |
| `/circles/new` | 项目组 | 生成**建团邀请链接**（固定 7 天有效），对方填资料注册即成为团长 |
| `/circles/[slug]` | 项目组 | 改互助团状态（运行中 / 暂停 / 已解散）、生成**团长转移链接** |

- 入口挂在 `/circles`（互助团网络页）：项目组看到"邀请创建互助团"与每个团的"查看"。
- **一个团只有一个团长**（第九轮起）：没有成员名单，也就没有"团成员管理"页；
  换人走**团长转移链接**，老团长的信息保留在「团长任期」里。
- 写权限在服务端兜底（`(workspace)/actions.ts` + 集合级 access）：非项目组即使直接 POST 也会被拒。

**「提名 → 发布」流程**（把矩阵里的"团长：提名"落到页面上）：

```
团长在「活动反馈」里对一条已采纳的反馈点「推荐发布」   ← 提名
        ↓
项目组在「精选发布」顶部看到「待发布的推荐」清单
        ↓
点「转成精选内容」→ 自动带出标题 / 摘要 / 日期 / 参与人数 / 现场照片 / 关联互助团
        ↓
发布成功 → 公众站成果流立即可见
```

- 推荐是**一个标记位**（`activity-reports.recommendedForPublish`），不是新集合，避免为了一个开关引入第二套治理流程。
- 已被转发的推荐标记为"已发布"，不能重复发布同一条反馈。
- 项目组仍可直接在「精选发布」新建精选（不强制走提名）。

### 4.9 通知列表（工作台 /notifications）

通知会一直攒下去（活动审批、报销核定、联系表单留言），所以这个页**必须分页 + 筛选**，
不能一把梭把全部拉回来铺在页面上。

**形态**：和资源页同一套——**一张表**（通知 / 时间 / 状态），装在卡片里；
卡片头部一行是筛选条（左边「全部 / 未读 / 已读」，右边标题关键字搜索框 + 清除筛选），
底部是分页器。

| 维度 | 口径 |
| --- | --- |
| 分页 | **服务端分页**，每页 20 条；页码写进 URL（`?page=2`），地址可分享、刷新不丢 |
| 筛选 | **已读状态**（全部 / 未读 / 已读）+ **标题关键字**（包含匹配） |
| 条件 | 筛选与页码都在 URL（`?read=unread&q=报销&page=2`），换条件时页码回到第 1 页 |
| 越界 | `?page=99` 之类越界页码回落最后一页，不给空白页 |
| 呈现 | 左侧「第 X–Y 条 / 共 N 条」，右侧上一页 · 页码 · 下一页；当前页 `aria-current="page"` |

- **筛选维度只留两个**：通知标题本身就把内容说清楚了（"提交了…的报销，请核定"），
  再分"类型"就要给集合加字段——不值得。
- **关键词输入防抖 300ms** 后写地址：边打字边翻页也不会丢字。
- 页码按钮用 shadcn `Button render={<Link/>}`（`console/Pager.tsx`），
  页数多时只留首尾与当前页附近，中间省略号。
- 空状态只说「没有符合条件的通知」，**不再放第二个「清除筛选」按钮**——
  筛选条上已经有一个，两个同名按钮会打架（实测踩过）。
- ⚠️ **输入框不要被服务端回传的值冲掉**：用户在导航落地前打的字，会被"从 props 同步输入框"
  那一步抹平。要记住**最后一次写进地址的值**，只在该值与它不同时才同步（`useRef`）。
- 窄屏：表格用 `.resp-table` 摊成卡片（标签在上、值在下），筛选条里的搜索框要
  `min-w-0 flex-1` 收缩——写 `w-full` 会按内容宽度撑开，横向溢出（实测 390px 溢出 63px）。
- **列序【状态 → 时间 → 通知】**（2026-11-01 第三十五轮）：
  状态在最左——进来先看「有没有还没读的」，一眼扫过去；
  通知列在最后并吃掉剩余宽度（`w-full`），右边不留空档。
  状态、时间两列**定宽靠左**（`w-[7.5rem]` / `w-[9rem]`）。

**点一条即读掉一条（2026-11-01 第三十四轮补）**

这一页**必须能单条标已读**——以前只有铃铛上的「全部已读」能清未读，
列表页点标题只是跳走（**合作类留言连跳都没有**，它没有 `link`），未读永远消不掉。

| 场景 | 行为 |
| --- | --- |
| 有链接的通知（活动审批 / 报销核定） | 点标题 → **先标已读再跳转**（拦默认行为，等服务端回包后才跳；否则跳转会打断请求，点了却没变已读） |
| 无链接的通知（合作联系留言） | 点标题 → 标已读，**停在原地**（无跳转目标） |
| 状态列 | 未读行给一枚显式的「标为已读」按钮——不靠"用户知道标题能点"，每行都写着怎么清未读 |
| 铃铛弹层 | 无链接的条目渲染成**可点的按钮**（以前是 `<div>`，点了没反应）；有链接的先标已读再跳 |
| 「全部已读」 | 服务端按「收件人 = 我 且 未读」**全量**处理（`markAllNotificationsRead`），不是只清弹层加载的最近 10 条 |
| 铃铛角标 | 显示**真实未读总数**（服务端 `count`），不是弹层那 10 条的未读数 |

- 交互在 `console/NotificationTable.tsx`（客户端组件），服务端动作 `markNotificationsRead`
  / `markAllNotificationsRead`；标完 `router.refresh()`，让分页签计数与角标一起更新。
- `markNotificationsRead` **逐条兜错**：集合的 update 权限只放行"还没读"的记录，
  重复标记会被挡回来——一条失败不能把整批「全部已读」带崩。
- ⚠️ **共享 Tabs 的窄屏坑**：分页签带计数后（全部 114 / 未读 0 / 已读 114），
  `TabsList` 会把整条工具栏顶出屏幕（实测 320px 溢出 9px）。
  修法在 `ui/tabs.tsx`：`Tabs` 加 `min-w-0 max-w-full`、`TabsList`（default 变体）允许横向滚动、
  `TabsTrigger` 加 `shrink-0`；选中线伪元素**收归 line 变体**（default 靠底色选中，
  多留一条透明下划线只会在横向滚动时撑出纵向滚动条）。

## 7. 路由与域名

### 7.1 三域（2026-10-24 第八轮定稿）

按国际通行做法把"公开内容 / 业务操作 / 系统数据"分成三个域，**域的职责互不重叠**：

| 域名 | 名称 | 内容 | 谁进得来 |
| --- | --- | --- | --- |
| 公众域（`localhost` / `www.mulan.org`） | 展示站 | 成果瀑布流、互助团版图、资料库、关于 | 任何人，**无登录入口** |
| 工作台域（`connect.localhost` / `connect.mulan.org`） | 业务工作台 | 方案 / 反馈 / 报销 / 审批 / 精选发布 / 邀请码 / 建团与团成员管理 | 团长、项目组 |
| CMS 域（`admin.localhost` / `admin.mulan.org`） | Payload CMS 后台 | 数据与集合管理（字段级、表格化） | **仅运维 / 技术负责人（独立 ops 账号）** |
| API 域（`api.localhost` / `api.mulan.org`） | 对外接口 | REST / GraphQL，**需要时**才单开 | 第三方集成（独立 API Key） |

命名约定：**`admin` 留给最高权限的数据工具**（与 WordPress Network Admin、GitHub Site Admin 一致），
业务工作台用 `connect`（或 `app` / `work`）。**不要**把 CMS 面板挂在叫 `api` 的域名下——
第三方按字面理解会去找接口文档，结果是个后台面板。

分流由 `src/proxy.ts` 按 `Host` 实现（Next.js 16 的官方约定是 `proxy.ts`，不再是 `middleware.ts`），
环境变量：`WORKSPACE_HOST`（工作台域，本地 `connect.localhost`）、`CMS_HOST`（CMS 域，本地 `admin.localhost`）。

各域的路径边界：

| 路径 | 公众域 | 工作台域 | CMS 域 |
| --- | --- | --- | --- |
| `/` | 展示站首页 | 工作台首页（rewrite → `/home`） | 302 → `/admin` |
| 工作台各页（含 `/home`） | **404** | ✅ | 302 → 工作台域 |
| `/admin/**`（Payload CMS） | **404** | 302 → CMS 域 | ✅ |
| `/api/**` | 仅公开集合（集合级 access 兜底） | ✅ | ✅ |

### 7.1.1 账号体系：业务账号与后台账号分离

- **业务账号**（`users` 集合）：**只有团长与项目组两种**，登录工作台（注册进来就是团长）。
  Payload CMS 后台**不接受**这类账号登录。
- **后台账号**（`ops-users` 集合）：运维与技术负责人，独立邮箱密码。
  `payload.config.ts` 里 `admin.user: 'ops-users'`——这是 Payload 的标准能力，
  业务账号根本不在后台的登录候选名单里。
- 后台账号在访问控制里按**全局管理员**处理（`access/index.ts` 的 `isOps`），
  等价于项目组的可见范围；`users` 的业务语义（谁是谁的团长）不适用于后台账号。
- 上生产再加：二次验证、审计日志、来源 IP 白名单。
- **CMS 后台完全用 Payload 原生界面**（英文、不汉化、不加提示、不做守卫页），
  只做一处改动：**隐藏登出按钮**——`admin.components.logout.Button` 挂
  `src/components/payload/HideLogoutButton.tsx`（返回 null，Payload 会用它替换默认 Logout 按钮）。
  权限边界靠**账号体系分离**表达（后台只认 `ops-users`），不靠页面文案。
- **连带后果**：后台改不了业务账号，所以成员与团的增删改**必须**在工作台完成
  （邀请注册 + 建团 + 团成员管理）——这是国际惯例（Shopify / GitHub 同理），不是缺陷。

```
/outcomes         活动列表
/outcomes/[slug]  成果详情
/circles          互助团版图
/circles/[slug]   互助团详情：该团是谁、做了什么、留下了什么
/resources        资料库
/resources/[slug] 资料详情
/about            关于
/contact          联系我们（合作与联系入口，不是注册入口）
```

旧的 `/activities` `/stories` `/events` `/library` 等路由已删除；
`/events` 保留为 301 到 `/`；资料库的旧名 `/library` 已改成 `/resources`，**不做兼容别名**。

> **互助团详情页是必需品**：版图页与成果卡上出现"杭州 AI 互助团"时，
> 它必须是一个能点开的入口（→ `/circles/<slug>`）。文案里写了"点进去看"，
> 页面就必须真的能点进去——**不许出现指向不存在路由的链接**。

### 7.2.1 404 与错误页

| 场景 | 处理 |
| --- | --- |
| 公众域访问工作台任一路径、`/admin`、`/login`、`/join` | **状态码 404**（不 302，不暴露路径存在性），正文为中文 |
| 公众域访问不存在的路径 | 渲染 `src/app/not-found.tsx`：**中文**、带站点头尾、给"回到成果流"的出口 |
| 管理域访问不存在的路径 | 同上（管理域也用中文 404，不出现英文 "Not Found" 裸文本） |

- 404 页面不得出现任何登录 / 注册入口（管理域除外，管理域的 404 可以给"回到工作台"）。
- 禁止用裸文本 `Not Found` 之类的英文短响应直接结束请求——访客看到的是"这里什么都没有"的死胡同。

### 7.3 工作台域路由（2026-10-24 第九轮：去掉 `/console` 前缀）

工作台在自己的域名下**不再带 `/console` 前缀**——URL 里每段都带 console 是噪音。

```
/                工作台首页（对外；统计可筛选，筛选条件在 URL 上）
/home            工作台首页（内部真实路径，由 proxy 重写到 /）
/activities      活动列表（按项目类型分组）
/activities/[slug] 活动详情（左信息 + 右侧活动进度；**发起活动也在这里**）
/circles         互助团网络（地图 + 列表）
/circles/all     全部互助团名录
/circles/new     邀请创建互助团（项目组）
/circles/<slug>  互助团详情（团长点「我的互助团」进的也是这个页）
/circles/[slug]  互助团详情（左信息右活动）
/assets          资源（**只有项目组**能进）
/login           登录
/join            邀请注册
/logout          退出
```

> 互助团这几条的**内部真实路径是 `/network/*`**（`src/proxy.ts` rewrite，URL 保持 `/circles`），
> 因为公众站本来就占着 `/circles`（互助团版图）。
> 早期那套 `/plans` `/reports` `/reimbursements` `/reviews` `/payments` `/invitations`
> `/cohorts/**` 分页已经**全部删掉**：工作台只有活动 / 互助团 / 资源三项导航，
> 其中「资源」还只给项目组（团长与成员看的是公众站的资料库）。

- **对外 URL 是 `/`，内部真实路径是 `/home`**：公众站已经占了 `/`，
  Next.js 不允许两个路由组提供同一路径，所以工作台首页由 `src/proxy.ts` 在
  工作台域把 `/` **重写**（rewrite，URL 不变）到 `/home`。
  其余页面都是真实路由，客户端导航不受影响。
- 工作台域的 `/admin` 跳到 CMS 域；CMS 域只服务 `/admin` 与 `/api`，其余路径 404。
- **公众域不屏蔽工作台路径**：那些路径在公众域本就不存在，落到 `app/not-found.tsx`
  （中文 404 + 站点头尾），不必维护路径清单。

> **域隔离靠 layout，不靠路径清单**：工作台与登录页各自有 layout，
> 进来先判断 Host——不在本域直接 `notFound()`（中文 404）。
> 这样"这个页面只存在于某个域"是**结构保证**，不是靠维护一张路径表。
> 路径清单会过期、漏项，layout 判断不会。

> 🔒 **不留兼容路径**：系统尚未上线，**没有"旧版本用户"要照顾**。
> 改路由、改域名、改字段时，旧的东西**直接删掉**，不做重定向、重写、兜底或双写——
> 不留"兼容旧链接"的跳转，不留 `@deprecated` 的兼容导出，不留别名账号。
> 发现任何"为旧版本留着"的代码，删掉。

### 7.3.1 三域路由一览

| 路径 | 公众域 | 工作台域 `connect.` | CMS 域 `admin.` |
| --- | --- | --- | --- |
| `/` | 首页 | 工作台首页（rewrite → `/home`） | 302 → `/admin` |
| `/activities` | 活动列表（rewrite → `/site-activities`） | 活动详情 `/activities/<标识>` | 404 |
| `/resources` | 公开资源 | 资源管理（rewrite → `/assets`） | 404 |
| 内部路径 `/home` `/network` `/assets` `/site-activities` | 404 | 404 | 404 |
| 工作台各页（含 `/home`） | 中文 404（路径不存在） | ✅ | 中文 404 |
| `/admin/**` | **404** | 302 → CMS 域 | ✅ |
| `/api/**` | 仅公开集合 | ✅ | ✅ |

### 7.4 网址术语表（2026-10-31 定稿）

同一个业务概念，地址栏里只用一个英文词。内部真实路径（为了让两个域共用同一路径而 rewrite 的那一层）**一律不对外**，直接访问 404。

| 概念 | 地址里的词 | 公众域 | 工作台域 | 内部真实路径 |
| --- | --- | --- | --- | --- |
| 活动 | `activities` | `/activities`、`/activities/<标识>` | `/activities/<标识>`（列表在首页） | 公众站 `/site-activities` |
| 互助团 | `circles`（参数 `circle`） | `/circles`、`/circles/<标识>` | `/circles`、`/circles/all`、`/circles/<标识>`、`/circles/new` | 工作台 `/network` |
| 资源 | `resources` | `/resources`、`/resources/<标识>` | `/resources`（管理清单） | 工作台 `/assets` |
| 经费 | `budget` | — | `/budget` | — |
| 项目（加油木兰 / AI豆计划 / 民宿管家） | 参数 `project` | `?project=a-idol` | `?project=go-mulan,a-idol` | — |
| 活动类别（技能提升类 …） | 参数 `kind` | `?kind=AI素养类` | — | — |
| 资源分类（品牌 VI …） | 参数 `category` | `?category=vi` | — | — |

- **同一场活动两边同一个标识**：工作台 `connect.xxx/activities/<标识>` ↔ 公开站 `www.xxx/activities/<标识>`。
- 界面用词与之对应：互助团归属叫「项目」，「类别」只指活动类别，「分类」只指资源分类。

## 8. 可访问性与性能

- 语义标签：`header` / `nav` / `main` / `section` / `article` / `footer`，页面里只允许一个 `<main>`。
- 所有图片有 `alt`；装饰性图片 `alt=""`。
- 焦点态可见：`:focus-visible` 必须有明确轮廓。
- 图片一律用 `next/image`，显式给宽高或 `fill` + `sizes`，禁止 `<img>` 裸写。
- 页面 `export const metadata`（Next 官方约定），禁止手写 `<title>` / `<meta>`。

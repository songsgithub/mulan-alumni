### 踩坑：dev 模式每次重启都会删掉 SQLite 的反向关系列

**现象**：新增集合后重启 dev，SQLite 里**表建好了，但关系列没了**
（`users` 表缺 `annual_budget_settings_id` 等），页面 500、报 `no such column: …`。
更要命的是：**手工补的列，下一次重启又被删掉**——所以"补一次"不管用。

**根因**：Payload 的 dev 模式会按 schema 重建表结构，但**不建反向关系列**
（关系字段在 `users` 上留下的那一列）。PostgreSQL 没这问题（关系存在 relationships 表里）。

**处理（已根治，不靠手工）**：

1. `npm run migrate:create` 生成迁移（生产 PostgreSQL 用这份，留在 `src/migrations/`）；
2. 新增 `scripts/fix-sqlite-relations.mjs`：把缺的列与索引补回来；
3. `payload.config.ts` 的 `onInit` 在初始化时调用它（0s / 3s / 8s 各一次，
   覆盖 dev push 晚于初始化跑完的情况）——**任何启动方式都会自愈**。

两个实现细节（都踩过）：

- 补列**不能带 `REFERENCES` 子句**：SQLite 开启外键约束时不允许
  「添加带 REFERENCES 的列」，会直接报错。Payload 的 SQLite 适配器本来就用列存关系，
  补一个普通整数列即可。
- 补列脚本必须是**独立 node 脚本、不进 Next 打包**：写成模块被 `onInit` import 时，
  Turbopack 会把 `node:sqlite` 当浏览器模块解析，报 `Expected a semicolon`。
  现在用 `execFileSync` 起子进程跑它。

⚠️ 生产是 PostgreSQL：直接 `npm run migrate` 即可，不需要这套补列。

### 修掉验收里最后一条失败：地图页「一次列出全部」（2026-10-30）

### 三个运营指标 + 字段排序（2026-10-30 补）

### 另一个坑：端口被占，"重启不了"（2026-10-30 已修）

我这边重启 dev 时占了 3000 端口，宿主再执行 `npm run dev` 就会 `EADDRINUSE`——
看起来像"系统起不来"。以后我重启前会先说一声，或者直接把进程交回给你自己起。

**2026-10-30 修掉了根因**：不是靠"记得说一声"，而是让启动脚本自己会接管。

- 端口 3000 上已经有**本项目**的实例时，`npm run dev` / `npm run dev:watch`
  会先停掉旧实例（含旧的守护脚本），再接管 3000；
- 端口被**别的程序**占着才报错，并说清是谁占的；
- 死进程留下的 `.next/dev/lock` 会被清掉（否则 Next 会以为"还有一个 server 在跑"）。

实测（同一个 WSL 里反复起停）：

| 场景 | 修之前 | 修之后 |
| --- | --- | --- |
| 守护实例在跑，再执行 `npm run dev` | `Another next dev server is already running.` + 退出 | 停旧实例、接管 3000、`Ready in 258ms` ✓ |
| 一次性实例在跑，再执行 `npm run dev:watch` | 同上 | 停旧实例、接管 3000 ✓ |
| 接管时会不会误杀自己 | — | 祖先进程（npm → sh → 脚本）已排除，日志只报旧实例的 PID ✓ |
| 接管后三个域 | — | 公众域 / 工作台 / CMS 全部 200 ✓ |

公共逻辑在 `scripts/dev-common.sh`；`npm run dev` 改走 `scripts/dev-run.sh`。

> ⚠️ **2026-11-01 更新**：上面提到的 `npm run dev:watch` 已删除，守护能力合并进
> `npm run dev` 本身（现在只有一个开发入口）。本节其余内容仍是当时的记录。
> 详见 AGENTS.md §8.75。

## 十三、验收过程中发现并修掉的问题

这些问题都是"页面能打开但链路跑不通"，必须记下来，避免回归：

| # | 问题 | 根因 | 处理 |
| :-: | --- | --- | --- |
| 1 | `npm install` 失败 `ERESOLVE: payload@undefined` | 本地镜像源未同步 Payload 3.92.0 | 安装时指定官方源；**不降版本** |
| 2 | `payload generate:types` 报 `Package subpath './with-plugin' is not defined` | `payload.config.ts` 用了 Payload v2 时代的 `nextPlugin()`；3.92 已无此插件，Next 集成由 `src/app/(payload)/` 下的路由直接承担 | 删除该插件与 import |
| 3 | `next build` 报 `./with-payload` 未定义 | 同上，3.92 的导出路径是 `@payloadcms/next/withPayload` | 改正 import |
| 4 | `s3Storage` 类型报错 `secretAccessKey` 不存在 | 3.92 把 AWS 凭证移进了 `config.credentials` | 按新结构调整；并把非上传集合移出 `collections` 列表 |
| 5 | 构建期预渲染 `/console` 报 403 | 工作台依赖登录态却被静态预渲染 | `/console` 布局加 `export const dynamic = 'force-dynamic'` |
| 6 | 全站上传功能不可用 | **根本没有定义 `media` 集合**，但所有文件字段都 `relationTo: 'media'` | 新建 `media`（公共媒体）与 `finance-evidence`（财务凭证）两个上传集合 |

## 十四、踩坑记录（给下一位接手的人）

1. **npm 镜像源没同步 Payload 3.92.0**：`registry.npmmirror.com` 上 `payload` 与 `@payloadcms/ui` 都还停在 3.91.0，而其余 `@payloadcms/*` 已经是 3.92.0，导致 `ERESOLVE: Found: payload@undefined`。装依赖请加 `--registry=https://registry.npmjs.org`。
2. **`npm install` 后 esbuild / sharp 的安装脚本被 npm 拦截**（`allowScripts` 机制），需要 `npm install-scripts approve esbuild sharp` 后 `npm rebuild esbuild sharp`。
3. **Node 版本**：`engines` 要求 `^22.23.4 || >=24.22.1`，本机 v24.22.0 会打 `EBADENGINE` 警告，但可正常安装与运行。
4. **Payload 3.92 的富文本渲染器**：官方入口是 `@payloadcms/richtext-lexical/react` 的 `RichText`，
   旧文档里的 `ReactRenderer` / `ReactRendererContextProvider` 在 3.92 **已经不存在**（`grep` 全包无此导出）。
5. **种子脚本不会自动读 `.env`**：`tsx` 不会像 Next 那样加载 `.env`，所以 `npm run seed` 要写成
   `tsx --env-file-if-exists=.env src/seed.ts`（已改好）。
6. **验收后要还原演示态**：`scripts/restore-demo.ts` 会删掉验收注册的账号、把邀请码恢复为 `pending`、并重算团成员数。
7. **Playwright 的 `fill()` 会往输入框注入 `style="caret-color: transparent"`**，这会让 React 在
   刷新时报"hydrated but attributes didn't match"。**这是测试工具的产物，不是应用缺陷**——
   改用 `pressSequentially()` 逐字输入后，控制台 error 数为 0（已复核）。
8. **Next.js 16 用 `src/proxy.ts`，不再用 `middleware.ts`**：构建产物里会显示 `ƒ Proxy (Middleware)`。
9. **`next/image` 的 `fill` 依赖父级 `position: relative`**：共享组件里漏了会让图片逃逸到整页（本次踩过，见问题 22）。
10. **重新 seed 后图片还是旧的**：Next 图像优化器按 URL 缓存，清 `.next/dev/cache/images` 再重启 dev。
11. **重置数据库前一定要先停掉 dev server**：Next 的 dev 进程会一直持有 SQLite 文件句柄，
    库文件被移除之后它仍在读**已被删除的旧 inode**，于是"重置了却看不到变化"，
    还会出现幽灵数据（如残留的验收记录抢占 Hero 位）。顺序必须是：
    `停 dev → 重建库 → migrate → seed → 起 dev`。
12. **端口冲突会让新 dev 起不来**：`npm run dev` 报 "Another next dev server is already running"
    时，旧进程还在服务旧数据。而且 **`pkill -x next-server` 杀不掉它**——进程名实际是
    `next-server (v16.4.3)`，`-x` 精确匹配匹配不上。要用：
    `ps -eo pid,cmd | awk '$2 ~ /^next-server$/ {print $1}' | xargs -r kill`
13. **`npm run migrate` 之后第一次 `npm run seed` 会撞 schema**：Payload 开发模式初始化时会 push schema，
    与迁移建好的索引冲突（`index ... already exists`）。种子脚本已改为以 production 模式初始化
    （`src/lib/seed-env.ts`），若手工跑 `tsx src/seed.ts` 请注意保留这行 import。
14. **改集合字段后 dev 报 `index xxx already exists` 并持续 500**：Payload 的 SQLite 自动 push 不是幂等的——
    新列与新索引会被建好，但它还会再尝试创建已存在的索引，于是 Payload 初始化抛错、整个站点 500。
    处理：`停 dev → DROP INDEX <冲突索引名> → 重启 dev`，索引会被重新建好；一轮不行就再重启一轮。
    （本轮踩到的是 `activity_reports_plan_idx`，重启一次即恢复。）
15. **验收脚本不能写死文案**：`/tmp/acceptance/run2.js` 曾断言 Hero 含「培训结束」，
    文案改成「课上完了，互助开始」后必然误报 FAIL。断言要跟着 `src/content/site.ts` 走。
16. **管理端多一个提交按钮就会打断验收脚本**：`button[type="submit"]` 在页面存在多个提交按钮时，
    Playwright 报 strict mode violation。脚本要用文字选择器（如 `button:has-text("发布到公开站")`）。
17. **Tailwind v4 的自定义断点会被"提前"排序**：写 `min-[1920px]:columns-4` 或在 `@theme` 里加
    `--breakpoint-3xl: 1920px`，生成的媒体查询会排在 `xl`（80rem）**之前**，
    于是 `xl:columns-3` 反而赢了。加 `!` 能糊过去，但不可维护。
    **正解**：宽屏断点写在 `globals.css` 的未分层样式里（如 `.masonry` / `.grid-4up`），
    未分层样式优先级高于 Tailwind 的 `@layer utilities`，顺序完全可控。
18. **改了组件类名要同步验收脚本**：瀑布流从 `columns-*` 换成 `.masonry` 后，
    `main [class*="columns-"]` 查不到元素，脚本会误报"瀑布流列数 = 0"。
19. **Playwright 的 `request` 上下文不解析 `*.localhost`**：`ctx.request.get('http://admin.localhost:3000/...')`
    会 `ENOTFOUND`。测子域要用 `page.goto`（观察最终 URL）或页面内 `fetch`。
20. **Payload Admin 的 `networkidle` 等不到**：后台页面有长连接（实时预览 / 心跳），
    `waitUntil: 'networkidle'` 会超时；用 `domcontentloaded` + 固定等待。
21. **域名换了，验收脚本里的管理端地址要跟着换**：`/tmp/acceptance/*.js` 的 `ADMIN`
    常量现在是 `http://connect.localhost:3000`（工作台），页面路径不带 `/console`。
22. **Playwright 的 `waitForURL('**/activities/**')` 会误匹配 `/activities/new`**：
    glob 里的 `**` 匹配任意层，要用正则 `/\/activities\/\d+$/` 才精确。
23. **HTML5 必填项会让脚本"静默失败"**：表单没填全时点击提交不会发请求，
    也没有报错日志——看 dev.log 会以为"功能没实现"，其实是校验挡住了。
24. **验收脚本里断言路径要用"精确匹配路径段"**：用 `href.includes('/circle')` 会把
    公众站的 `/circles` 误判成管理路径——要写成 `href === w || href.startsWith(w + '/')`。
23. **改路由目录后要重生成路由类型**：`npx next typegen`；
    否则 `.next/types/validator.ts` 仍引用已删除的旧路径，TypeScript 会报一片假错。
24. **CLI 窗口"突然自己关闭"怎么查**（2026-11-02 实录）：不是任务跑崩，是**终端 / WSL 侧被关掉**。
    排查路径按这个顺序走，一次就能定位：
    - `~/.minimax/v2/observability/cli/incidents/` —— 里面有 `cli_unclean_exit`（下次启动时的崩溃恢复）
      与 `cli_terminal_error`（终端真死了，会有 `EIO: i/o error, write` + `terminalDead: true`）。
      **如果这个目录里没有当次的异常文件，说明进程是被 SIGKILL 硬杀的**（可捕获的 JS 异常一定会落盘）。
    - `dmesg -T | head` —— 看有没有新的 `Linux version ... WSL2` 启动横幅。
      **有横幅 = WSL 整个重启过**，那一轮跑的东西全部作废，且与代码无关。
    - `~/.minimax/v2/sqlite/runtime-state.sqlite` 的 `local_runtime_sessions` —— 会话 `status` 会被标成
      `interrupted`，`error_message` 是 `This session was interrupted because the previous local runtime stopped.`，
      `error_source` 是 `crash-recovery`。
25. **崩溃后要把"没跑完的那一步"重跑，不能靠回忆补**：

## 十七、第三十八轮之二：表格断行与图片排版（2026-11-02）

### 一、这一轮要解决什么

用户反馈：「一张图片就占了一页纸，剩下的全留空白」。

上一轮（§8.76）把版式按 GB/T 9704-2012 排了一遍，**规范项全绿**，

1. **表格到处断行**——「计划活动时间」这类六字标签被挤成两行，
   日期「2026年10月31日」断成「31日」+「计划活动地点」；
2. **照片一张一页**——每张拉满版心宽（156mm），高度按原图比例就有 89~129mm，

### 二、版心宽度的实测依据

不是拍脑袋放宽的，是量出来的：

```
标签列需 ≥ 36.0mm
日期列需 ≥ 42.9mm
地点列需 ≥ 55.7mm（10字，会换行可接受）

一行四列至少需要 ≈ 170.6mm 版心宽
  版心 156mm → ✗
  版心 176mm → ✓
```

版心宽从 156mm 放宽到 **176mm**（左右白边 28/26mm → **17mm/17mm**），
上下白边仍按公文的 37/35mm。

> ⚠️ **这是一处对公文的偏离，已在打印路由注释与 AGENTS.md §8.77 写明理由**：
> 这份材料是「活动立项与结项记录**表**」，表格是主体而不是纯文稿。
> 表格宽度是设计约束，页边距要让位于它。
> 若项目组要求严格按公文版心，需把字段表四列改成「标签上行、内容下行」的竖排结构。

### 三、表格断行的根因与修法

| 根因 | 修法 |
| --- | --- |
| `table-layout: fixed` + 百分比列宽，把六字标签挤到 26.5mm，而 `nowrap` 又不让它换行 → 标签自己断行 | 改 `table-layout: auto`，交给浏览器按内容分配 |
| auto 布局下 `colgroup` 变成「建议值」仍干扰分配 | 移除 `fields` 表的 colgroup（数据表的保留） |
| 费用明细表 7 列，8pt 内边距吃掉约 40mm，「活动场地与布置」只剩 25mm | 内边距压到 5pt |
| 中文短标签被拆成「活动场地与布」+「置」 | 短标签加 `nowrap`；长地址与长文本仍按需换行 |
| 地址被拆成「微工」+「厂」 | `line-break: strict; word-break: normal; overflow-wrap: break-word` |

### 四、图片排版

- **照片**：打印路由里按「版心高贪心装页」逐张算尺寸——能两张挤一页就挤，
  宽幅图不撑爆页，组内**顶部对齐**（不垂直平分，否则图浮在页面中间）。
- **票据**：按「版心宽 × 版心高」双重约束缩放，并**垂直居中**
  （原来顶部对齐，下方留 128mm）。
- **图与图注绑定**：`figure` 加 `break-inside: avoid`（原来照片在第 4 页、图注跑到第 5 页）。

### 六、踩坑记录（给下一位接手的人）

1. **模板字符串里的反引号**——在 `page.evaluate(\`...\`)` 内的注释里写

2. **Python 批量替换 TS 文件**——替换串里手误把 `//` 写成 `#`（Python 注释），

## 十八、第三十八轮之三：图片与版心同宽（2026-11-02）

用户：「但是上传的图片就小了，是否可以让图片与页面同宽，但是可以根据页面需要，适当调整高度（不是裁剪）？」

### 一、问题

上一版（第三十八轮之二）把照片按「一页放 N 张」分组、组内平分页高，

### 二、改了什么

| # | 项 | 改法 |
| --- | --- | --- |
| 1 | 照片尺寸算法重写 | **宽度 = 版心宽（176mm）**，高度 = 宽度 × 原图宽高比，**保持原始比例，不裁剪、不拉伸**；只有算出的高度超过一页能放下的高度才**等比整体缩小** |

| 1 | 上下白边 | 37/35mm → **15/15mm**，版心高 225 → **267mm**（版心宽仍是 176mm，左右没动） |
| 2 | 照片排版 | **固定分高度为 2 份**：版心高 ÷ 2 = 一个槽位（133.5mm），一页放两张 |
| 3 | 图片缩放规则 | 槽位内**按原比例缩放到最大**（宽上限 176mm、高上限 121.8mm），**不裁剪、不拉伸、不变形** |
| 4 | 票据排版 | 同一条槽位规则：两张开销后正好排满一页；只剩一张时仍**垂直居中** |

### 二、为什么是「等比缩放」而不是「压扁」

满宽 176mm 的 4:3 照片高 131.5mm，两张连图注要 290mm，装不进 267mm 的版心——
**满宽 + 两张 + 不裁剪 + 不变形，四者不能同时满足**。

- 「压扁」能凑满宽，但合影里的人物会被压矮、看着像渲染坏了；
- 等比缩放后照片仍有 147~162mm 宽（版心宽的 84%~92%），仍是宽幅大图，
  比上一版的 80~89mm 缩略图好得多。

取舍写在打印路由的注释里，改法就在同一处。

### 三、两个踩坑

1. **打印尺寸不能写进共享 CSS**：`docCss` 同时供 PDF 路由与工作台页面版预览使用。
   把槽位高度（`max-height`）写进 CSS，会把**页面版**的照片也限高——
   预览容器比 A4 宽得多（实测 948px），限高后图在盒子里左右留白（只画 616px 宽），
   页面版反而比改动前更小。现在槽位规则只由打印脚本写**行内样式**（行内样式优先）。
2. **判「图片是否顶到高度上限」要把边框算进去**：图片有 0.6pt 边框画在**外侧**，
   PyMuPDF 量到的是内容框，比脚本写进去的尺寸小两个边框（2×0.21mm）。
   不算这 0.42mm，每张满高的图都会被误判成「没顶到上限、却又不是满宽」。

## 二十、第四十轮：图片满宽 + 等高（宽屏、不裁剪、可压扁）（2026-11-02）

### 一、改了什么

| # | 项 | 改法 |
| --- | --- | --- |
| 1 | 图片宽度 | **满宽 176mm**（上一轮是 147~162mm 的「按比例缩到槽位里」） |

| 3 | 裁剪 | **不裁剪**：`object-fit: fill`，整张铺满设定框，一点内容不少 |
| 4 | 变形 | **只压扁、不拉长**：统一高度 = min(槽位上限 118mm, 该份材料里最矮那张图的自然高) |

指向注释里的 CSS 属性名，**真正的原因（反引号）很难一眼定位**。
在 `docCss` / `page.evaluate` 的模板字符串**内部**写注释，
**一律不要用反引号**。仓库已有 `scripts/check-template-backticks.mjs` 专门守这条。
